# 需求：零信任（0.3.0-alpha1）

目标版本：**0.3.0-alpha1**。决策见 `docs/decisions/0030`、`0031`，设计见 `design.md`，任务见 `tasks.md`。

## 背景

0.2.x 的 Hub 是完全可信的：它验证登录、运行主管、保存全部数据和模型 Key，并直接给 Node 下指令（`docs/api/core-hub-node.md`）。Hub 一旦被攻破，攻击者就能在所有机器上执行任意代码、读取全部数据，还能让所有 Node 安装任意二进制（`node.update` 的 `repo` 由 Hub 指定）。

## 威胁模型

| 假设被攻破（不可信） | 假设完好（可信） |
|---|---|
| 服务器（原 Hub，之后的中继）：root、数据库、内存、日志、TLS 证书、域名解析 | 用户的设备（手机、电脑）和设备上的 Passkey |
| 网络上的任何一方（中间人） | 用户指定的“大脑机器”（在 AI 的权限范围内，见 S6） |
| 全部源码（攻击者知道每一处实现） | 每台 Node 机器自身（它只对自己负责，见 S5） |
| GitHub 账号和 CI | 离线保管的发布密钥 |
| 任意一台普通 Node（见 S5） | Vercel 账号（托管页面代码，单独加固，见 design §9） |

安全只来自密钥，不依赖实现保密。源码泄露不降低安全；源码被篡改由发布签名防住。

## 安全要求

- **S1 只有用户的指令会被接受。** Node 只执行由用户签名、或由用户授权的大脑在授权范围内签名的指令。中继、其他 Node、网络上的任何一方都伪造不出能被接受的指令，也重放不了旧指令。
- **S2 中继看不到数据。** 聊天、笔记、会议、任务、Run 的输出和 diff、仓库列表、模型 Key、MCP 配置，经过中继和存放在中继上时都是密文。中继只能看到元数据：谁在线、什么时候有流量、数据量多大。
- **S3 中继无法冒充任何一方，也无法插入中间人。** 配对时交换的公钥用一条不经过中继的高熵通道认证；之后所有通信都固定在这些公钥上，不依赖 TLS。
- **S4 关键操作只能由用户本人完成。** 关键操作每次都要求一次新的 Face ID、指纹或 Windows PIN（WebAuthn 用户验证），并且由 Node 或大脑自己验证这次断言，不信任页面说的“已验证”。关键操作的清单见 design §5。
- **S5 一台普通 Node 被攻破，只损失这一台。** 它不能给其他机器发指令，读不到其他机器的数据，也读不到聊天记录，无法冒充用户。踢出后它读不到之后的任何数据。
- **S6 一台大脑机器被攻破，影响以 AI 的权限范围为限。** 它能做的不超过 AI 本来就能做的事（项目自主范围内）。超出范围的操作要用户点一下，关键操作要用户本人的 Face ID，它都伪造不了。它读不到它不参与的项目。
- **S7 更新不能被劫持。** Node 只安装用离线发布密钥签过名的版本，下载地址写死；安装更新本身是关键操作。
- **S8 能检测到中继的破坏行为。** 中继可以丢弃、延迟、重排、重放消息，或者拿出旧的名册、旧的状态，但这些都会被检测到并提示用户，不会被悄悄接受。中继拒绝服务（停止转发）防不住，但用户会知道。
- **S9 密码学强度。** 只用标准的、经过审计的算法和库，不自己发明协议原语。抗暴力破解：任何密钥都不从人能记住的密码派生；低熵输入只出现在有硬件防重试保护的地方（设备的 PIN）。加密采用经典算法和抗量子算法的混合，防止“现在截获、以后解密”。
- **S10 项目文件不加密。** Node 磁盘上的代码、git，以及推送到 GitHub 的内容都和现在一样。加密只针对经过中继和存放在中继上的数据。

## 使用要求

- **U1 一次解锁。** 启动 app 时用 Face ID、指纹或 Windows PIN 解锁一次，直到退出或自动锁定都不用再验证（关键操作除外）。
- **U2 自动锁定可调**：1 分钟、5 分钟、15 分钟（默认）、1 小时、4 小时、永不。按设备分别设置。
- **U3 日常不碰密钥。** 没有主密码，也不设恢复码。用户可见的秘密只有：每接入一台新机器时一次性的配对串。
- **U4 AI 自主运行不打扰用户。** AI 自己发起的任务不需要 Face ID，也不需要点击，只要在项目自主范围内。超出范围的操作在 app 里点一下就行（不用 Face ID）。
- **U5 大脑机器由用户指定**（关键操作），系统从中自动选出当前的中心；中心掉线后自动由下一台接任。所有大脑机器都离线时，AI 停止工作、任务排队，app 仍然能查看缓存、踢出或冻结机器。
- **U6 快速踢出。** 在机器列表里左滑“踢出”，刷一次 Face ID，一步完成。另有“冻结”（可恢复，不需要 Face ID）和“全部暂停”（立刻停止 AI 的所有活动，不需要 Face ID）。
- **U7 页面托管在 Vercel**，用用户自己的域名。
- **U8 丢失全部 Passkey 的后果可以接受**：聊天等数据永久无法解密；每台 Node 在本机执行 `sous trust reset` 后重新配对。项目文件不受影响。

## 不在范围内

- 用户自己的设备被攻破（被植入木马、在解锁状态下被他人拿走）。
- 大脑机器被攻破后在 AI 权限范围内的行为（S6 只保证不超出范围）。
- 模型供应商能看到发给它的提示和代码。
- 中继的拒绝服务和元数据泄露。
- 子 agent 被提示注入后，在授权范围内通过网络把数据带出去（由 Node 的硬规则缓解，不在本 spec 解决）。
- 服务器作为部署目标、同时又是 Node 的情况：这台 Node 和中继同处一台宿主机，不受保护（design §11）。

## 验收

1. **恶意中继测试套件**全部通过：伪造签名、重放、重排、丢弃、回滚名册、配对时替换公钥、拿出旧的租约和旧的事件日志、把一个项目的密文挪到另一个项目，Node 和 app 都拒绝并提示用户（design §12）。
2. **被攻破的普通 Node 测试**：让一个 Node 进程拿着自己的密钥，尝试给其他 Node 发指令、读取其他项目的数据、冒充大脑，全部失败；踢出后读不到之后的数据。
3. **被攻破的大脑测试**：大脑在自主范围外发指令、发关键操作、读不参与的项目，全部失败。
4. **中继数据库检查**：跑完一轮完整流程（聊天、任务、Run、审批、笔记、会议）后，在中继的数据库和日志里搜索已知的明文片段，一条也搜不到。
5. **使用验收**（真机）：iPhone PWA、macOS Safari 或 Chrome、Windows Chrome 或 Edge（Windows Hello PIN）各走一遍：解锁、自动锁定、关键操作、踢出、AI 自主任务、大脑切换。
