# 0010 权限策略是安全网，执行隔离放到第二期

- Status: Accepted
- Date: 2026-11-03

## Context

sous 的权限判断依赖子 agent 通过 ACP 发起权限请求。但每个 agent 都有自己的权限配置：它已经允许的操作会直接执行，sous 根本看不到。底线规则按命令文本匹配，换个写法就能绕过。

## Decision

- 在默认和自动审批模式下，子 agent 必须以“每个操作都询问”的方式启动，把权限判断全部收归 sous；只有在完全开放模式下，才允许它按自己的规则放行。
- 明确承认：第一期的权限模式和底线规则是**安全网，不是安全隔离**，用来防止误操作，不防恶意绕过。
- 来自外部的内容（网页、文件、子 agent 的输出）只当作数据，不能改变权限。
- 真正的执行隔离放到第二期：macOS 用 seatbelt，Linux 用 bubblewrap 或 landlock，能用 agent 自带沙盒的（比如 Codex）优先用。

## Alternatives

- 第一期就做操作系统级沙盒：三个平台的实现差异很大，会严重拖慢核心闭环的交付。
- 完全信任子 agent 自己的权限配置：审批语义不统一，用户看不到全貌。

## Consequences

- 在第二期之前，不要在存放敏感资料的机器上使用“完全开放”模式。
- 0005 定义的操作分类表，第二期可以直接复用为沙盒规则的来源。
