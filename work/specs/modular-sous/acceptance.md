## 2026-11-20 · 第一方 ACP 可用性与边界

- **实际推理**：Apple Silicon 上用本机 Qwen3.5-9B（Q4_K_M，llama-server 回环服务），真实 Chromium Passkey 登录。浏览器收到第一方 ACP 子进程的 WebSocket 回复增量；模型经 MCP stdio 创建 `inbox` 任务而非执行 Run。重启后切回无主管，历史/工作区状态保留。只发送了测试内容，没有外部模型请求。
- **确定性验收**：以本机 SSE 夹具重复实际子进程与 MCP 交互；验证只暴露白名单、未知派发参数被拒绝、重复草稿返回同一 ID、运行中取消并把停止结果保存到历史。Go 竞态与工具边界测试验证项目对话只见本项目名称和 ID，不能越权读全局记忆/写其他项目，自动回合不能建任务，过期回合凭据不能调用。
- **应用回归**：Core 全量测试、`go vet` 与 ACP/Hub/主管竞态测试通过；桌面测试和 `go vet` 通过；Web 42 文件、316 项通过，1 项既有跳过。macOS arm64 与 Windows amd64 开发包重新构建。Windows 是交叉构建，不代表安装、签名或真机结果。

## 2026-11-20 · 本机授权运行器（Apple Silicon / macOS 26.5）

- **真实链路**：选择一次性的本地目录或文件；在核对两个官方运行时文件 SHA-256 后，用固定 Alpine OCI 镜像摘要启动无网络 Guest（不挂载宿主项目）。实际运行命令验证未授予的宿主文件和 `.env` 不可见，HTTP 无法出站，新增/修改/删除仅作用于 Guest；宿主文件原样保留。确认销毁后才导出含前后副本与校验值的审阅报告。一次冷路径从运行器入口至报告约 7.22 秒，含镜像拉取；不作为 SLA。一次 registry 别名路径出现间歇授权错误，最终改用官方 registry 端点的固定 arm64 单清单摘要和匿名拉取，并实测冷仓库 `--offline` 拒绝联网、预置镜像后离线再次执行成功。
- **拒绝与中断**：临时夹具覆盖路径中的符号链接、硬链接、FIFO、选择磁盘根和尺寸上限；Guest 返回链接时拒绝导出；命令超时后确认销毁。CLI 测试在 Guest 命令已启动时真实 SIGKILL 宿主执行器，无报告落地；重启只做对账，确认旧 Guest 不存在并清除日志标记，再启动新 Guest 正常导出。
- **兼容性**：Core 全量 `go test ./...`、`go vet ./...`、Windows/Linux amd64 交叉编译通过；后两者不启用本机沙盒，无实体机回退。该阶段的执行器未加入桌面包，不接 Hub 派发；执行阶段不写回原始文件。

## 2026-11-20 · 本机审批写回（真实 Microsandbox + Git worktree）

- **执行和写回分开**：真实 Guest 用合成 Git worktree 的普通文件副本；`.git` 工作树指针和 `.env` 未被导入。运行、销毁并导出后，Git 跟踪文件无变动。执行单独的审阅和下发逐文件授权后，才出现预期增、改、移除。另一个 worktree 不变，手工并发编辑的文件拒绝写回。
- **写回边界**：新增不覆盖目标；同一次报告内获准新建目录可继续写入该次报告审阅过的其他文件。修改保留本机模式、扩展属性和原件；移除也保留原件。真实 APFS 测试覆盖替换目录、符号链接、竞态编辑、过期审阅版本、篡改产物、单文件授权不能扩展成目录。交换后窄窗口不是系统级锁，发现冲突则报告并保留恢复材料。该 CLI 阶段未覆盖多文件原子应用或 Desktop 可视审阅。
- **离线可复现**：官方仓库的冷启动直拉再次实测遇到间歇错误，增加了显式 `download-image`，逐层校验并另存为供离线启动的 OCI 归档；用该归档在全新运行时目录完成同一组真机测试，不依赖 Guest 或运行阶段在线拉取。

## 2026-11-20 · 本机工作台派发接入原生桌面（真实包）

- **真实端到端**：用隔离 `HOME`/`SOUS_HOME`、合成 Passkey 和只含 `note.txt` 的临时项目启动重新打包的 `build/desktop/sandbox-preview/sous.app`。从真实 Chromium 创建任务并点击请求，桌面沙盒窗口刷新后显示同一任务标题和说明；说明明确只供参考，不会作为命令执行。桌面重新选择项目目录、输入命令并经过系统确认，私有继承管道完成 `list → claim → heartbeat → complete`，真实离线 Microsandbox Guest 退出码为 0。
- **审阅和写回**：浏览器在完成后只看到 `ready` 和 `1 项变更`，宿主项目仍只有原始 `note.txt`。桌面审阅页显示新增 `native-result.txt` 的前后内容，第二次单文件确认写回后宿主才出现该文件，文件内容正确。任务状态仍为 `inbox`，本机沙盒回执不会替换任务工作流。
- **撤回**：第二轮运行执行 `sleep 120`，浏览器请求停止后实际 HTTP 状态先变为 `cancel_requested`，桌面通过两秒周期心跳收到停止要求，Guest 被确认销毁且没有产生报告或 `should-not-exist.txt`，随后完成回执为 `cancelled`。宿主已有写回结果未被覆盖。
- **体验修复**：沙盒页提供「打开本机工作区」入口；工作台状态轮询在非活动页放慢、恢复可见时立即刷新。Hub 状态查询改为只读查询，避免移动端/浏览器轮询占用写事务；状态转换仍在后续变更事务中原子完成。

## 2026-11-20 · Apple Silicon 桌面原生沙盒验收

- **包内真实流程**：独立 `build/desktop/sandbox-preview/sous.app` 在 macOS 26.5 启动，使用 WKWebView 内置页、系统文件选择器和系统确认。指定合成目录、本机运行时与离线镜像，在 Guest 新建 `result.txt`。界面确认 Guest 已销毁并显示变更文本，审核前核对宿主尚无新文件；随后单独确认写回，原宿主文件不变，新文件内容符合预期。未连接旧工作区或上传内容。最终包还复验了重开已有报告、二进制变更无法在图形界面写回、完整文本可确认写回；确认宿主仅得到选中的文本。
- **发现并修复**：最初内置页面未收到 WebView 桥回应；修复固定本机消息通道和页面就绪信号后通过。真实选择长路径时又命中 Microsandbox socket 长度限制；改为按本地工作区生成隔离的短运行时路径并复验成功。

## 2026-11-20 · 内置主管热切换（独立本机 Hub）

- Chromium + 带用户验证的虚拟 Passkey + 真实 ACP 子进程和 MCP 工具桥：模拟本机模型返回 503 时保持现有绑定。接通后浏览器无需刷新即可使用 ACP；切换过程中项目、任务、记忆和主对话 ID 不变，已有待授权沙盒请求保持为待授权。
- 在模型仍忙时请求切换返回 `binding_busy`，不截断旧回合；可以显式停止 ACP，后续仍可切换。旧绑定暂停接单、退出并撤销本轮工具桥后再启动新绑定。防旧设置页写入用持久化 `generation` 检查。用已选择的配置快照完成旧回合：修改磁盘配置不会重定向。重启检测到档案改变进入无主管状态，直到再次显式连接并通过探测。
- **真实模型复验**：回环 llama-server 的本机 Qwen3.5-9B 通过显式连接探测；浏览器在热切换后收到真实回复增量并确认最终回复落库。仅发送合成数据；故障矩阵仍使用上面的可控夹具。
- 范围：仅支持 App 目录的无主管、兼容主管与第一方 ACP。第三方/异地 ACP 生命周期、真实老数据升级、附件与会议仍必需单独验收。

## 2026-11-20 · 独立 HTTPS 云 Hub（隔离部署验收）

- **一份权威工作区，不依赖用户电脑**：实际启动 `sous hosted-hub`，用专用测试域名、测试证书和真实 HTTPS/WSS。Chromium 用手机尺寸及触控、虚拟 Passkey 完成登录，创建对话、项目、任务和记忆；没有启动任何个人电脑 Node 或 Relay。服务重启后原 ID 和历史仍在；模拟 `/me` 暂时不可用时保持在云工作区，明确重试、不回落到其他工作区。登出切断已建立的 WSS，重新用 Passkey 登录通过。修复了手机输入焦点变化造成发送按钮移动、点击落空的问题。
- **首次授权及启动边界**：两个独立且已准备好提交的 WebAuthn 注册请求并发完成，只一个成功。初始化链接仅在私有文件，未出现在 HTML 或服务日志；单权威锁拒绝同目录第二进程，拒绝把旧数据库误当云工作区或把云数据库改用另一 HTTPS origin。HTTP 核对通过：异站或缺 Origin 的写请求拒绝；旧配对、设备、Node、终端和宿主文件入口没有开启；无执行模块时不能把手工任务直接变成执行。
- **单机同区装配预演**：另跑完整 HTTPS 套件，选配实际第一方 ACP 子进程及 MCP 工具桥，模型用回环 SSE 夹具模拟；在没有个人 Node 时收到回复并落库。不是云厂商网络、真实云模型耗时或多设备接入证据。
- **Linux 二进制**：Linux amd64 构建成功；Linux arm64 二进制在真实离线 Microsandbox Guest 中运行，通过回环后端的启动、初始授权、拒绝旧 Node、停止和重启。Guest 不联网，不涉及公共云实例分配或发布签名。

### HTTPS 保存确认网络基线

无主管，Chromium 手机视口，暖连接，带宽为 1 MB/s 下载 / 256 KB/s 上传；每组丢弃 3 次预热后测 30 次。客户端计时是提交到收到 `202`；Hub 计时取 `Server-Timing` 的写入和事件内部发布耗时。只测合成小消息，不计模型、首次连接、任务执行或文件上传。

| 追加延迟 | 客户端 p50 / p95 | Hub 写入 p50 / p95 |
|---|---:|---:|
| 0 ms | 7.5 / 11.9 ms | 0.30 / 0.85 ms |
| 80 ms | 94.3 / 99.2 ms | 0.77 / 0.93 ms |
| 180 ms | 196.2 / 200.2 ms | 0.72 / 1.37 ms |

80 ms 场景达到当前拟议的确认门槛 p95 ≤ 300 ms。**不代表实际公网**；该夹具没有涵盖真实跨区链路、代理缓冲、抖动、队列并发、大传输、真实模型首字或工作机冷启。不要由此推断公网 SLA，也不要把模型响应速度归因于 Hub 规格。

## 2026-11-20 · 托管执行：真实 Microsandbox Guest、持久化与再唤醒

- **真实端到端**：合成工作区通过真实 HTTPS、Chromium 手机尺寸和 Passkey 登录；浏览器从任务详情选择文件、确认 Guest 命令。专用 worker 无任务不启动 VM；授权后领取，启动无网络 Microsandbox，保存检查点、确认回收 Guest，Hub 落库后浏览器可查看成果。未使用个人电脑 Node 或旧配对接口。
- **丢失回执**：通过隔离 TLS 测试中继，在 Hub 持久化结果后暂扣返回，真实强杀 worker；检查点存在、Guest 已回收。重启 worker 只补交幂等结果并清理检查点，不重跑命令。再次重启 Hub，用另一任务显式选用上次结果由全新 Guest 读取、产出并保存新成果。
- **撤回与边界**：浏览器撤回已进入真实 Guest 的长任务，worker 收到撤回后清理，无部分结果。测试覆盖重复请求、过期租约不可覆盖、不能拿其他项目的成果或改派指定本机的任务；Owner Cookie 和 worker Bearer 接口不混用。
- **范围**：以上是 Apple Silicon 参考 worker；每次销毁的是 Guest，未操作真实云厂商实例、电源或账单。Linux/KVM 云执行、短时实例引导、云资源按需分配与回收仍待验收。同步落盘开启后的本机暖连接复测（每组 30 次）：追加 0/80/180 ms，消息保存确认 p95 分别 13.5/100.5/202.6 ms；80 ms 场景 Hub 写入 p95 1.83 ms。没有包含实际公网或云工作机冷启。

**发布闸门未通过**：尚未验收隔离的第三方 ACP、旧配对数据库迁移及附件/会议；未接入远程 Node 的常在线授权通道。独立 HTTPS 云 Hub 已在隔离环境验收，公共域名、实际手机、反代部署与多设备接入未验收；托管执行已用真实 Guest 验证，公有云 VM 归零、外部 MCP 和高级混搭尚未开通。Windows/Linux 的真实沙盒及实机体验、网络延迟矩阵、正式签名与安全发布验收均未完成。下一阶段必须以真实 Agent/VM/部署验收为准，不能把 mock 或交叉编译当成实机支持。

## 2026-11-20 · Linux/KVM worker 构建与领取前预检

- **实现**：显式的 `sous_linux_worker` + CGO 构建覆盖 Linux amd64 和 arm64，固定各架构的 Microsandbox v0.7.16 官方 `msb`、固件及 Alpine OCI blobs。普通纯 Go Linux Hub 不链接执行 SDK。Linux worker 在领取前检查实际 `/dev/kvm`、固定运行时和离线镜像；失败退出，无宿主回退。桌面文件选择、审阅与写回仍独立于 hosted worker。云材料直接以限额内的字节副本导入 Guest，不在宿主创建中转项目；Guest 对账标记在创建前、清除后同步目录；检查点损坏或写入中断时不清理未对账 Guest。仍按「检查点 → 销毁 Guest → Hub 回执」顺序。
- **Linux 证据**：两种架构的 CGO worker 和 `localrun` 测试二进制交叉构建通过；依赖检查确认普通纯 Go Linux Hub 不含 Microsandbox。纯 Go Linux arm64 Hub 也在真实 Guest 通过启动、路由边界及重启冒烟。交叉构建的 arm64 worker 在真实无网络 Linux Guest 中退出码为 1，指明缺少 `/dev/kvm`，未创建运行时、未到领取步骤。此证据只证明拒绝路径；当前主机无 KVM，未跑通 Linux 上的正向 Guest 启动。按 [Linux/KVM 验收方法](../../tests/integration/README.md#linuxkvm-worker-发布验收)在实际服务账户下另验，不把这次结果记为 Linux 支持。
- **回归**：Core 全量、`go vet`、`cloudwork` / `cloudworker` / `localrun` 竞态测试通过。Apple Silicon 真实 Guest 通过本机导入、执行、审阅写回、强杀恢复和管道停止测试。Chromium 手机布局的 HTTPS 托管执行 E2E 通过，新增离线镜像无效或有未对账 Guest 标记时作业均仍为 `queued`，且标记不被改写；再次验证真实 Guest 取消、持久化后丢失回执与重启只补交、跨 Hub 重启复用成果。仍未实施云厂商控制器或验收实例资源归零。

## 2026-11-20 · 按需云工作机容量控制与代次隔离

- **控制面与权限**：新增独立 `sous cloud-controller`；SQLite 状态与授权队列同事务。仅可执行的已授权任务创建预留，草稿/聊天/指定本机任务不启动。管理 Bearer、一次性引导和逐代会话不同权，控制面不回传脚本或材料；静态模式保持兼容，已迁入托管的工作区不能用静态密钥降级绕过代次。重启恢复原预留，且只用同一短时引导注册一个 worker。

## 2026-11-20 · 独立 AWS EC2 驱动、故障对账与引导恢复

- **代码与打包**：`sous-ec2-driver` 使用 AWS SDK v2，由原容量控制器通过 stdin 接入，不把 AWS SDK 链入普通 Hub，也不给 worker 传 AWS 角色或管理 token。配置绑定工作域、账户、区域、子网、安全组、自有 x86_64 AMI、小型嵌套虚拟化实例和加密根盘。已提供 Linux amd64 驱动/worker 交叉构建、cloud-init 短时引导和 systemd 单元，未制作或启动实际 AWS AMI。独立二进制以合成配置在本机初始化、读取持久 ledger 并拒绝重新初始化；未做 AWS API 调用。
- **协议与故障证据**：AWS SDK 用合成凭据向回环 fixture 发送签名 Query 请求，验证单实例、稳定 `ClientToken`、开启嵌套虚拟化、无公网 IPv4、IMDSv2、加密/随实例删除的根盘、精确终止与根卷核对的真实序列化。故障测试覆盖发请求前持久化、回执未知、临时查不到时不假定不存在、冷启动撤回阻止迟到创建、重试只能沿用同一启动请求、未知旧发请求不能被之后的拒绝抹掉、根卷遗留和陌生实例保护。AWS 回复 `shutting-down` 不等同 `terminated`，根卷遗留则继续保留这一代。Core 全量、`go vet` 及相关竞态测试通过。
- **真实 Guest 回归**：托管和静态两条 HTTPS/Chrome/Apple Silicon E2E 均通过。托管套件于强杀 worker 后移除一次性引导文件，验证同代持久会话仍能只补交已保存检查点、不重跑；确认下一代真正的 Guest 能复用成果。这是模拟 `/run` 消失后的进程恢复，不是 EC2 操作系统重启。
- **未过的门槛**：尚无获准隔离 AWS 测试账户、区域/预算及自有 worker AMI 的实际验收记录；未在 AWS 上创建、终止、计费或验证 Linux/KVM。下一步按 [EC2 运行手册](../../../docs/guides/ec2-worker.md)连接明确获准环境，测真实公有云链路和闲置资源清理，不能把本地 AWS 协议 fixture 作为实例归零证据。

## 2026-11-20 · 托管项目的受限外部 MCP

- **实现**：独立、默认关闭的托管 `/mcp` 与 OAuth 入口，不调用主管或旧 Node。注册固定 HTTPS 回调的公开客户端，用 PKCE S256、精确 resource、一次性短授权码、短时访问令牌与轮换刷新，Hub 只保存摘要。所有者明确选择一个未归档项目，默认只读，可另勾选创建 `inbox` 草稿。工作台「外部连接」列出授权及有效期并可撤销，新草稿在与授权核对相同的事务中写入。
- **官方 SDK 与故障**：独立 MCP Go SDK 客户端 over TLS 通过初始化、工具发现、项目/任务读与幂等草稿；验证只读不出现写工具、跨项目 ID 拒绝、无仓库字段与执行 Run。OAuth 用例验证错误回调/资源/PKCE、重复和过期授权码、摘要存储、访问过期、刷新轮换和重放撤销。未把测试客户端称为 ChatGPT 认证。
- **真实浏览器验收**：真实 HTTPS 和手机 Chrome 视口、WebAuthn 虚拟认证器、隔离注册回调。从授权页选项目、启用草稿、外部 HTTP 独立换码和创建，到工作台看到同一 `inbox` 草稿并撤销。原凭据随即返回 `401`；浏览器 Cookie 不能代替 MCP 身份，默认关闭时 `/mcp` 返回 `404`。独立开/关套件、以及与真实 Apple Silicon Guest 托管 worker 的组合复跑均通过。组合首次有一次已保存成果选择等待超时，补充 API 与 UI 两层断言后的复跑未重现，不算弱网或稳定性 SLA。
- **回归及边界**：Core 全量、`go vet`、外部 MCP/Hub/任务竞态、Web 类型检查和 317 项 Web 测试通过（1 项既有跳过）。此能力只覆盖运维预注册客户端和托管 Hub；第三方产品的注册/互操作、跨本机/云工作区切换和公网端到端仍单独验收。[接口契约](../../../docs/api/core-external-mcp.md)。
