# 0013 人员就是岗位档案，不是有记忆的拟人员工

- Status: Superseded by 0024（岗位改成“agent + 模型 + 定位”的预设，定位不再拼进提示词）
- Date: 2026-11-04

## Context

M5 起 sous 围绕项目、人员、任务三个实体管理工作（`work/specs/m5-workbench`）。“人员”有两种定义：一是可配置的岗位档案（agent、模型、岗位说明），和机器无关；二是“某台机器上的某个 agent”。另外还可以给人员加长期记忆和性格，做成拟人员工。

## Decision

- 人员 = **岗位档案**（persona）：名字、头像字和颜色、使用的 agent、会话选项（模型、思考强度）、岗位说明、默认权限模式、适合的任务类型。
- 岗位和机器无关。干活时，一个岗位在某台机器上占一个工位（机器的并发槽位），同一个岗位可以同时在几台机器上各做一个任务。
- 选 agent 的顺序：任务指定的 agent > 岗位的 agent > 项目默认 agent > 全局默认。岗位的会话选项优先于机器的默认值，但不能覆盖 sous 为权限模式强制设置的选项。
- 岗位说明拼在任务提示的最前面。岗位不保存跨任务的记忆；长期经验写在项目上（项目说明、仓库里的 AGENTS.md）。
- 第一次启动时创建五个内置岗位（后端、前端、审查、运维、助理），用户可以改、删；删掉的不会再被创建。

## Alternatives

- 人员 = agent × 机器：和算力一一对应，但机器离线“人”就没了，换机器等于换人。
- 有记忆的拟人员工：每个 Run 都是新的 ACP 会话，agent 本身没有连续性，装出来的记忆会误导用户。

## Consequences

- 总览按“项目 × 机器”画格子，格子里画岗位头像；同一个岗位可能同时出现在几个格子里。
- 任务多了 `persona_id`，Run 记下岗位名和会话选项（`persona`、`options`）。
