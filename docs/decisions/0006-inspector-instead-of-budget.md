# 0006 不设花费上限，由巡检 agent 监督

- Status: Accepted
- Date: 2026-11-03

## Context

sous 会自主运行，失控的循环可能消耗大量 token。花费上限需要按模型配置单价，配置起来麻烦。

## Decision

- 第一期不做花费上限。
- 每次调用模型都记录 token 用量（几乎没有额外成本）。
- 看门狗分两层：
  - 进程看门狗（不用模型）：检查心跳，进程挂了就重启，再从事件日志断点恢复。
  - 巡检 agent（用模型）：定时巡检（默认 10 分钟一次），看任务是否运行过久或长时间没有进展、是否在重复调用同一个工具、token 消耗速度是否异常。按严重程度决定暂停、终止，还是只通知用户。

## Alternatives

- 按天、按任务设花费上限：配置麻烦，第一期价值不高。

## Consequences

- 以后要加花费上限，可以直接复用已经记录的用量数据。
