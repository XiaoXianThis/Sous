当你同时维护多个项目、手头有两三台电脑和服务器、并且交替使用 Claude Code、Codex、Cursor、OpenCode 等编程 agent 时，最消耗精力的往往不是写代码本身，而是**切窗口、找终端、配环境、盯进度、点权限审批和搬运上下文**。

`sous` 的定位是**你的副主厨（sous-chef）**：一个长期运行、随叫随到的私人 AI 助理与多 Agent 调度中枢。

## 1. 为什么叫「副主厨」：三个角色的分工

在法餐后厨（Brigade de cuisine）里，主厨不亲自切每一盘菜，而是把意图交给副主厨，由副主厨统筹各个档口并把关出品。`sous` 采用同样的分工：

| 角色 | 对应谁 | 负责什么 | 不做什么 |
|---|---|---|---|
| **主厨（Chef）** | **你（用户）** | 提出想法、跟主管讨论方案、在关键权限与交付节点拍板（审批 / 合并 / 推送 / 开 PR） | 不必守在某台电脑前盯终端、不必手动创建和清理大量临时分支 |
| **副主厨（Sous-chef）** | **主管（`sous-hub`）** | 常驻在线、记住你的偏好与项目背景、用只读工具查小问题、唤醒「项目顾问」深聊代码、把需求拆成任务、挑选「Agent + 模型」预设派发到在线电脑、跟进结果并向你汇报 | **绝不直接执行 shell 命令**，也不越权自动合并主分支或强推远端 |
| **档口厨师（Line Cooks）** | **子 Agent（Claude Code / Codex / Cursor / OpenCode / Kiro）** | 在目标开发机或服务器的隔离目录（`worktree` / `in_place` / `scratch`）中执行具体编码、测试、排查或部署任务，通过 `sous mcp` 报进度、遇到分歧主动提问、结束时交结构化结果 | 不跨出本地策略边界，命中底线规则的操作被 Node 直接拦截 |

## 2. 什么时候用 `sous`

- **不在电脑前，也想推进开发或处理审批**：服务端 `sous-hub` 托管了针对桌面三栏与手机端 iOS Liquid Glass 深度适配的 PWA。走在路上用手机跟 `sous` 说一句「帮我查一下登录接口为什么 500，修好后跑一遍测试」，家里的开发机就会在独立 worktree 里拉起 Claude Code 或 Codex 干活；需要权限时推通知到手机，点一下「允许这一次」即可继续。
- **多台开发机与服务器协同工作**：笔记本、工作室台式机、云端 Linux 服务器都通过 `sous` 客户端接入同一个 Hub。主管知道每个项目在哪台机器的哪个目录，会自动把代码任务派给在线的开发机，把部署任务派给角色为 `server` 的服务器。
- **混用多家编程 Agent 与模型**：把常用的「Agent + 模型 + 思考强度」存成**预设（Preset）**（例如「Claude Opus 深度重构」「Codex 快速修单测」「Kiro 常规改动」），任务之间随时切换，不受单一厂商绑定。
- **不想让 AI 弄乱当前工作区**：代码任务默认在 `~/.sous/worktrees/<仓库名>/<任务短id>` 的独立分支上执行，你正在编辑的原始工作区纹丝不动；就地任务（`in_place`）也会先在影子仓库拍快照，随时可以一键还原。

## 3. 核心架构边界：Hub 只动脑，Node 才动手

为什么不直接让云端服务器 SSH 到你的电脑，或者在云端跑一个全能容器？

因为 `sous-hub` 部署在公网可达的服务器上，集中保存了对话历史与模型 API Key。为了保证即使公网入口出现风险也不会危及你的开发机与生产环境，`sous` 严格拆分为两端（详见 [系统架构](/docs/architecture-overview) 与决策记录 `0002`）：

1. **大脑 `sous-hub`（服务端）**：
   - 常驻在 Linux 服务器（或本地开发环境），维护单一事实来源的 SQLite 事件日志（`eventlog.Log`）。
   - 负责运行主管模型、审批模型（`approver`）、验收模型（`reviewer`）、巡检模型（`inspector`）与长对话摘要模型（`compactor`）。
   - 提供带内网防护的联网搜索与网页抓取（`web_search` / `web_fetch`）。
   - **没有任何执行本机 shell 命令的代码路径。**
2. **执行端 `sous daemon`（客户端 Node）**：
   - 运行在你的 macOS、Linux、Windows 开发机或服务器上，**主动外连** Hub 的 `/node` WebSocket，本机无需开放任何入站端口，也不需要公网 IP。
   - 通过标准 **ACP（Agent Client Protocol）** 启动本机已安装并登录的编程 agent。
   - 在本地强制执行权限模式（`default` / `auto` / `open` / `readonly` / `verify`）、目录边界与不可绕过的**底线正则规则（Floor）**。

## 4. 你可以从哪里访问 `sous`

所有入口共享同一条主线对话（也可按项目开启作用域隔离的「项目对话」）与同一个事件流：

- **桌面端网页工作台**：三栏布局（左侧导航栏 + 中间等高项目卡片网格 + 右侧可调宽对话栏），支持在项目弹窗内直接浏览修改文件、查看 diff、原地批复权限，以及打开受近期 Passkey 保护的项目本机终端。
- **手机主屏 App（PWA）**：在手机浏览器打开 Hub 地址并「添加到主屏幕」，获得全屏 Liquid Glass 界面、手势返回与 Web Push 实时通知（待审批、任务完成、受阻提醒）。
- **本机终端 `sous chat`**：在已运行 `sous daemon` 的电脑终端里直接执行 `sous chat`，无需再次登录即可收发消息、切换线程与批准权限请求。
