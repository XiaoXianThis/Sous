# 0016 模型在页面上配置，存在 Hub 的数据库里

- Status: Accepted
- Date: 2026-11-04

## Context

原来 Hub 自己用的模型（主管、验收、审批、巡检）写在 `hub.yaml` 的 `providers` 和 `roles` 里，API Key 放在环境变量里，改了要重启。用户想随时切换模型和思考强度，添加多个供应商、每个供应商多个模型，而且配置要存在后端，换设备也一样。

## Decision

- 供应商（名字、协议、地址、模型列表、`api_key_env`）存在 `model_providers` 表，API Key 存在单独的 `model_keys` 表；每个角色选哪个供应商的哪个模型、思考强度多少，存在 settings 的 `models.roles`。它们和 settings 一样是本地配置，不进事件日志；改动只追加一条不含密钥的 `models.changed` 事件，让页面刷新。
- 运行时每个角色拿到 `models.Registry.For(角色)`：每次调用模型时查当前的选择，所以切换后下一次调用就生效。没单独选的角色跟主管用同一个。用量记录的是实际回答的模型。
- `hub.yaml` 的 `providers`、`roles`、`efforts` 变成可选：第一次启动、数据库里还没有供应商时导入一次（Key 仍然从 `api_key_env` 读），之后以数据库为准。
- 页面：设置里新增“模型”页（角色的模型和思考强度、供应商的增删改、从供应商读取模型列表、试一下）；聊天栏标题旁边可以直接切换主管的模型和思考强度。
- 安全：API Key 从不通过 API 返回；添加、修改、删除供应商要求近期验证过 Passkey（地址决定 Key 发到哪里，被盗的 Cookie 不能把它改到别处）；地址只能是 https（本机除外）。切换角色的模型不需要再验证，只能在已有的供应商里选。

## Alternatives

- 继续用配置文件，加一个“重新加载”：仍然要登录服务器改文件，手机上没法切。
- 供应商和角色走事件日志：Key 不能进只追加的事件表，把配置拆成两半（事件 + 密钥表）没有好处；settings 已经是同样的先例。
- 给 Key 加一层加密存储：加密的密钥只能放在同一个数据目录里，偷到数据库的人也偷得到它，实际没有提高安全性。

## Consequences

- 不用重启就能换模型；多个供应商、多个模型都能在页面上管理。
- 数据库里有 API Key 的明文，`data/` 目录和备份要按密钥对待（备份文件权限 600）。
- `hub.yaml` 里的模型配置第一次之后就不再生效，文档里说明了这一点。
