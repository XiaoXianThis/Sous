# 本机 Microsandbox 执行预览

`sudo`、Docker、云账号都不需要。当前只支持 **Apple Silicon Mac**。`sous-sandbox` 可作为本机命令使用，也可装入独立的桌面开发验收包。不接受 Hub、旧 Node、浏览器或远程主管的执行命令；独立本机工作台可发送待桌面确认的任务请求。

## 准备

1. 在仓库运行 `wok run core build-sandbox`。二进制输出到 `build/core/`。
2. 从 [Microsandbox v0.7.16 官方发布](https://github.com/superradcompany/microsandbox/releases/tag/v0.7.16) 取得 `msb-darwin-aarch64` 和 `libkrunfw-darwin-aarch64.dylib`，存放在自己的本机目录。对照发布校验清单核验；确保 `msb` 具有可执行权限。Sous 启动前还会重新校验这两个文件的 SHA-256，不会自动下载或使用不同版本。
3. 准备一个小的测试项目和一个现有的结果目录。结果目录不能是项目或运行时目录的子目录。运行时默认在本机用户目录的 `.sous-sandbox`，项目和运行时不能重叠。运行时路径有长度上限；需要时用 `--runtime-home` 指定父目录已存在的短路径，首次使用需要空目录。

## 使用桌面沙盒工作台

1. 准备 Core 和 WebUI，运行 `wok build core web`，然后 `wok run core build-sandbox` 和 `wok run desktop build-sandbox`。在 `build/desktop/sandbox-preview/` 中找到独立的 `sous.app`。请不要把未正式签名、公证的验收包当作公开发行包。
2. 若正在运行另一份 Sous，先退出那份托盘程序。启动沙盒开发包，然后从 Sous 托盘菜单打开「本机沙盒与审阅…」。在「运行时与离线设置」选择已核验的两份 Microsandbox 文件；需要完全离线时，也可选择下文生成的 OCI 归档。运行时配置会在本机记住，项目授权不会。
3. 使用系统选择器选择合成测试项目，比如只含一个文本文件的目录。输入 Guest 命令，例如 `printf 'sandbox result\n' > result.txt`，确认只授权这一次。命令只在 Guest 内运行。等待运行结束、销毁回收后，窗口会切到「审阅」。
4. 选择一个变更查看原件和结果，独立确认「写回这一项」。图形写回需要先查看未截断的文本；二进制或超长文本可以从「在访达查看」打开产物目录，自行审阅后使用下文的 CLI。可以重新选择之前生成的结果目录审阅。本机产物不会同步到远程工作区。

## 关联本机工作区任务

在内置 Sous 工作台打开待分配或待办任务，点「请求本机沙盒」。回到桌面的「本机沙盒与审阅」，刷新请求并选中任务，然后**重新**选择本次授权的目录或文件、在本机输入 Guest 命令并确认。任务说明只供参考，不是命令，也不能替代授权。结束后工作台仅显示状态与变更数；审阅和写回仍在桌面，任务不会自动完成。

未领取的请求可直接在工作台撤回；已领取则用「请求停止」，等状态变为已撤回。桌面也有「停止并清理」。如果工作台提示中断而非已撤回，先在桌面「运行时与离线设置」中对账清理，并检查本机报告，再决定是否重新请求。请求不会自动重跑。

## 运行并审阅

将示例占位路径替换成实际的绝对路径。选择一个文件或目录只授权这一次；`--` 后的命令在 Guest 中执行，工作目录为 Guest 的项目副本。先用 `ls` 查看内容：

```bash
build/core/sous-sandbox --source "<测试项目绝对路径>" --output "<现有结果目录>" --msb "<msb 的绝对路径>" --firmware "<固件的绝对路径>" -- /bin/ls -la
```

首次运行需要宿主通过官方仓库匿名获取固定摘要的 Linux arm64 Alpine OCI 镜像；**启动后的 Guest 禁用网络**。镜像已有缓存时可在 `--` 前加 `--offline`，禁止拉取；缺少缓存则失败，不尝试联网。项目不会挂载进 Guest。导入跳过隐藏文件、常见凭据和依赖目录；不会跟随符号链接或硬链接，拒绝特殊文件及项目范围内的子挂载。不能将整个用户目录或磁盘根作为项目。单文件上限 2 MiB、总共 32 MiB、最多 1024 项。筛选不是通用密钥检测，试用时请选合成或无敏感信息的素材。

命令完成并确认 Guest 销毁后，输出一个 `sous-result-*` 结果目录。`manifest.json` 列出相对路径、增加/修改/删除和前后文件 SHA-256；可以手动在自己信任的对比工具里打开各条 `before_artifact` / `after_artifact`。`guest.log` 为截断后的 Guest 输出。运行结束只导出本机审阅材料，**不会自动写回原目录**。Guest 的产物和日志可能不可信，审阅前不要执行或直接打开为网页。

## 审阅后写回

先关闭正在自动保存这些文件的编辑器或其他程序，再从 `review` 获取审阅版本和变更清单。`preview` 提供按校验值复核的前后文本（最多 64 KiB），二进制和截断文件请检查对应原始产物。决定接受某项后，在本机单独执行 `apply`；每条命令只接受一个精确的相对文件路径：

```bash
build/core/sous-sandbox review "<结果目录绝对路径>"
build/core/sous-sandbox preview "<结果目录绝对路径>" "<revision>" "src/example.txt"
build/core/sous-sandbox apply "<结果目录绝对路径>" "<revision>" "src/example.txt"
```

只有正常完成、仍保留本机授权记录的结果可以写回。写回没有目标目录参数，只针对运行时选定的原文件或目录。同名新文件不会覆盖已有文件；原始路径被替换、原件内容不同、授权范围不符或审阅材料已变化时会拒绝。支持新增、修改、移除普通文件；改名可视为分别确认新增和移除，不会移除目录。修改需要支持克隆与原子交换的文件系统（已实测 macOS APFS），以保留本机文件权限和扩展属性。

修改或移除会在文件原本的父目录保留 `.sous-writeback-*` 原件，输出 `local_backup`，并在结果目录留下 `writeback-*.json`。移除指移出原路径，不是删除原件。确认应用、安全备份、以及文件没有仍在被软件使用后，可在本机清理这些隐藏恢复副本；不要提交或推送它们。系统会在替换前复查原件，替换后再核对被换出的原件；若发生紧贴替换动作的并发冲突，会报错并保留可能含用户并发修改的原件，**不要忽略错误或自动重试**。这不是跨所有编辑器的协作锁，也不是多文件事务。

## 预先准备离线镜像

如果首次拉取不稳定，或需要在另一个具备可信运行时的本机完全断网启动，先在获准联网时运行：

```bash
build/core/sous-sandbox download-image "<待创建 OCI 归档的绝对路径>"
```

命令仅匿名读取固定公开镜像，逐项校验清单、配置和镜像层，不读取项目或本机仓库凭据。之后在普通运行命令的 `--` 前加 `--image-archive "<归档绝对路径>"`；运行器会重新验摘要并在该次运行中禁止拉取。缓存已有时也可以只用 `--offline`。不要用常规 `msb image save` 的重新编码归档代替上述固定原始 OCI 镜像。

## 中断恢复

正常退出和取消都会尝试强制销毁 Guest。若进程被强制杀死，使用同一个运行时目录再次启动前会先对账；也可以只清理而不读取任何项目：

```bash
build/core/sous-sandbox --recover --runtime-home "<先前使用的运行时目录>" --msb "<msb 的绝对路径>" --firmware "<固件的绝对路径>"
```

清理没得到确认时，运行器不会给出完成报告，不会启动新的 Guest，也不会回退到实体机执行。保留运行时目录用于恢复，不要在 Guest 还在运行时手动删除它。
