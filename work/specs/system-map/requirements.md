# 系统页：实时查看模块之间怎么配合和运行状态

## 修订（2026-11-11）

第一版按 S1、S4、S7 做成了 React Flow 的拓扑图。用户看了以后觉得乱、看不清数据流转：拓扑图回答的是“谁和谁连着”，用户要的是“此刻谁把什么交给了谁”。所以页面改成**模块协作的实时时序图**：

- S1、S4 改为：每个参与者一列（你、接口、主管、模型、外部工具、任务引擎、机器连接、机器、定时与巡检、推送），时间往下走，每一行是一次交接，画成两列之间带文字的箭头；默认只画模块之间的配合，“显示底层细节”才画事件日志、页面推送和轮询。
- S5 改为：列头和行都点开弹窗（不再是右侧面板）。
- S6 改为：“在系统页里追踪”把页面筛成这一件事（任务、Run 或对话）的全部交接，同一个筛选也能在页面上选。
- S7 改为：暂停后列表停住，新来的攒着，点“回到实时”继续；不再有时间轴。
- 不再依赖 `@xyflow/react`。

其余需求不变。画法见 `docs/architecture/system-map.md`。

## 现状

- 架构只写在 `docs/architecture` 的 mermaid 图里，是静态的，会过时，也看不出系统此刻在做什么。
- 运行状态散在各处：机器页（在线、工位）、工作台（任务、Run）、用量页（token）、上下文表（窗口占用）。主管卡住了、事件堆积、某个供应商一直报错、副作用队列积压，都要翻日志才能发现。
- 一个任务从派发到汇报经过哪些模块、卡在哪一步，看不到。

## 需求

- S1 架构图页面：桌面左侧图标栏加“系统”，点开后工作台区域换成整页的架构图（React Flow 绘制）。从左到右分层：客户端（界面、命令行）→ 接口 → Hub 内的模块 → 外部服务和机器（模型供应商、MCP 服务、搜索引擎、推送服务、每台机器一个节点）。
- S2 图来自代码：模块和连线由 core 里的注册表 `internal/sysmap` 声明，不是手画的。每个事件类型都要归到一个分组，每个 Hub ↔ Node 帧类型都要标明方向；新增事件或帧而没有登记时，单测失败。
- S3 运行状态：每个模块显示状态（正常 / 忙 / 空闲 / 降级 / 停止，图形加文字）、一句话说明和 1～2 个带文字的数字，每秒刷新。
- S4 数据流转：连线上实时显示流量，有数据经过时出现流动动画，速度和深浅按最近 5 秒的次数变化；悬停显示最近 1 分钟的次数和最近 3 条摘要（经过脱敏）。
- S5 详情：点击模块打开右侧详情面板：完整状态、子项（每个对话、每台机器、每个服务）、近 15 分钟的次数走势、实时流量记录（可以暂停）、相关对象的链接。点击连线显示它承载的内容和最近的记录。
- S6 追踪：在任务详情、Run 详情和对话标题栏里有“在架构图里追踪”，打开架构图并高亮这个对象最近 15 分钟内走过的连线，按时间列出每一步；还在进行的那一步所在的节点闪烁。
- S7 回放：可以暂停实时更新，拖动时间轴查看最近 15 分钟内任意一秒的流量。
- S8 手机：设置里多一项“系统状态”，按层列出模块和状态，点进去看详情，不画图。
- S9 安全：只有 Passkey 登录后能看，设备令牌不能访问。摘要经过 `redact` 打码，不包含消息正文、终端输出和密钥。
- S10 开销：没有人打开页面时，Hub 只做原子计数；有人打开时每秒最多推送一帧汇总。不写数据库，也不进事件日志。

## 不做

- 在图上操作系统（暂停任务、重启模块）。这一页只用来看，操作入口仍在原来的页面，详情面板里给出链接。
- 长期的指标存储和告警。
- 机器内部的细节（本地策略的拒绝次数、sous mcp 的连接）。机器节点只显示 Hub 已经知道的信息：在线、工位、正在跑的 Run。
