# 主线长期对话

主线是用户和主管之间一条永远不结束的对话：系统事件、主动汇报、任务进展都会进来。它要能一直聊下去，几个月以后依然记得之前定下的事，而且每轮的花费不会随着时间一直涨。

## 现状

- 每轮只取线程最近 40 条消息（`supervisor.HistoryMessages`），再把画像记忆（最多 10 条）、按最近 3 条用户消息召回的记忆（最多 6 条）、机器和任务环境拼进系统提示。
- 问题：
  1. **健忘**：第 41 条以前的内容直接看不到，没有摘要。没被写进记忆的决定、承诺和上下文就这样丢了。
  2. **没有 token 上限**：按条数截，不按 token 截。几条贴了大段日志的消息就能撑爆窗口，到时候只会报错。
  3. **缓存几乎不命中**：系统提示里有精确到分钟的时间、会变的任务状态和每轮不同的召回记忆，它们在请求最前面，导致后面的历史消息每轮都不命中缓存。超过 40 条以后，窗口滑动也会让开头每轮都变。Anthropic 请求没有设置 `cache_control`，完全不缓存。
  4. **找不回原文**：模型没有办法查看更早的对话。

## 需求

- R1 一条线程可以无限聊下去。每轮请求的输入 token 不超过所用模型窗口的固定比例；超过时自动处理，不报错给用户。
- R2 不健忘：
  - 已做的决定、未完成的承诺和待办、用户的偏好和纠正，不会因为整理上下文而消失；
  - 任何更早的内容，模型都能在需要时查回原文。
- R3 缓存友好：两次整理之间，每轮请求的前缀只增不改，只有最后一段（最新消息和本轮环境）不同。目标是两次整理之间的输入缓存命中率达到 80% 以上（DeepSeek、OpenAI 自动缓存，Anthropic 显式断点）。
- R4 看得见、管得了：页面上能看到当前占用了多少上下文、缓存命中率、上次整理的时间和摘要内容；用户可以手动触发整理，也可以直接修改摘要。
- R5 整理失败不影响对话：降级为按 token 预算截断，下一轮再试；不阻塞回复。
- R6 主线和项目对话都适用。主线优先验收。
- R7 完整历史仍然只保存在事件日志里，整理过程不删除、不改写任何消息；页面照样能往上翻全部历史。
