# Sous 模块化架构：讨论结果

> 讨论快照：2026-11-19；本机沙盒选型更新：2026-11-20。本文记录需求、已定方向、首版建议和未决项，不代表运行时代码已经实现。
> 配套：[新架构图](architecture.md) · [技术设计](design.md) · [实施与验收任务](tasks.md)

## 1. 我们要解决的不是拆目录，而是拆职责

用户安装的是一个完整的 **Sous App**，而不是一套要自己安装和连线的进程。App 按场景装配 Hub、Agent、Node、WebUI 等模块，负责启动、探活、停止和配置；模块可以随包、同机、跨进程或远程部署。**可插拔不等于每个模块都是微服务，也不等于首版要做插件市场、动态加载或任意拓扑。** 桌面包可以同时带 Hub、Sous Agent、本机 Node 能力和内置 WebUI；不启用某模块不影响其他模块有意义地工作。不为模块化先重写框架、移动应用目录或新增 `apps/*`。

| 模块 | 负责 | 不负责 |
|---|---|---|
| **Hub** | 工作区的权威数据和工具箱：聊天与可迁移上下文、记忆、项目、任务、Run、审批、事件、确定性调度和计划触发；提供业务 API 与 MCP 工具，负责 ACP 回合编排 | 不内置主管、模型供应商或推理循环；不直接跑工作区命令，不替本机用户授予文件权限 |
| **主管 Agent** | 可换的「大脑」：通过 ACP 接受回合，通过 Hub MCP 查记忆/项目、建任务、提交判断；可用第一方 Sous Agent 或通过验收的第三方 Agent | 不拥有 Hub 数据库、审批权、Node 执行身份或默认的宿主项目访问权 |
| **Node + 执行 Agent** | Node 管理执行能力、按权限准备工作区、启动执行 Agent、执行 Run、回报进展与结果；执行 Agent 在同一执行环境内通过 ACP 工作 | 不持有全局业务状态，不是主管，不因上线而成为 Hub |
| **WebUI** | 对话、项目、任务、审批、连接与设置；桌面、手机浏览器使用同一套工作台能力 | 不承担调度，不直连各个 Agent 或 Node，不另存一套权威任务状态 |
| **接入 / Relay、沙盒管理、云工作机控制器** | 可选基础设施：承载已授权连接、本机隔离或云计算生命周期 | 不是业务 Hub；现有盲中继不变成明文业务代理，云资源管理凭据不交给 Agent |

**每个工作区只有一个权威 Hub。** 用户可以拥有本地与云端两个独立工作区并切换连接，不把同一个工作区做成本地云端同时接单、双写的双主系统。「当前主管」「Hub 所在机器」「执行机器」是三个不同概念。首版一个 Hub 绑定零个或一个主管；同一个 Agent 产品可担任不同角色，但实例身份、工具作用域和会话要分开。

## 2. 用户提出的组合及优先级

沿用对话原编号；没有第 3 项。首版优先打磨全本地和标准托管两条路径，**不是否定其余需求**。独立模块和统一边界是基础；把所有组合同时产品化、做无缝双主同步才是暂不承担的复杂度。

| 原编号 / 需求 | 连接与数据位置 | 取舍和实际限制 |
|---|---|---|
| **1 · 隐私优先，完全离线** | 桌面内置 WebUI → 本地 Hub ↔ 本地主管；执行时用本机沙盒 Node。聊天、记忆、项目状态和文件留在本机；不需要云账号或 Relay | 优先支持。Agent 跑在本地不等于模型离线；必须选可离线运行的模型、Agent 与工具，关网验证，而不是仅凭部署位置承诺离线 |
| **2 · 网页远程聊天，Hub 留家里** | WebUI 经认证入口连接家庭 Hub；云 Sous Agent 服务作为该 Hub 的远程主管，调用 Hub 工具。云服务不接管权威状态 | 高级组合。家庭 Hub 必须在线；真正发给云主管的上下文、工具结果不是「从未离开本机」。不能把云主管当作 Hub 故障接管 |
| **4 · 云 Hub 管多台电脑，本地主管（如 Codex）** | 本地桌面直接连接托管工作区，本地主管经适配器接入云 Hub；各 Node 分别接入同一云 Hub，不要求用户在网页聊天 | 云 Hub 是需要的，远程主管接入是高级组合。主管电脑离线时云 Hub 仍可手动管理和派发给其他在线机器，不会暗换成云主管 |
| **5 · 云 Hub + 云 Sous Agent** | WebUI 或桌面 → 常在线云 Hub ↔ 同机或同区域云主管；再按需派到本地或云 Node | 标准托管路径。保持主管可选；没有 Node 也能聊天、查数据与规划。个人电脑全关时可以执行已授权且材料在云端的任务 |
| **6 · 用外部 Agent 客户端访问项目** | 例如用户习惯的 ChatGPT 类客户端，在具备兼容 MCP 能力且用户授权时 → Hub 的受限 MCP 接口；Hub 按正常流程派发 | 不必安装或打开 Sous 桌面才能管理，不必把外部客户端注册为主管，也不绕第一方 Agent 再转发。首版内部 MCP stdio 不等于已经对外提供远程 MCP；逐客户端验证兼容与授权 |
| **7 · 桌面与外部 Agent 都要，本地和云都可用** | 多入口可操作同一工作区；桌面可选择不同的本地/云 Hub 连接，每个工作区的 Node 归各自的权威 Hub 派发 | 支持入口并存和工作区选择，不承诺本地与云端同一工作区双写、透明同步、自动迁移或同一 Node 的跨 Hub 共享授权 |

**为什么多机仍需要云 Hub：** 多台电脑连同一个 Hub 本身不要求上云；但家庭 Hub 是控制平面的可用性单点。它关机、停电或断网时，即使其他电脑在线，家庭 Hub 也无法接收或派发新任务。托管 Hub 消除对那一台家庭主机的依赖；它不能唤醒物理断电的机器，也不能取得仅存于离线机器上的文件。手机可在没有主管的情况下手动建任务、审批和调度；需要 AI 对话再配置可用的主管。等待本地机器的任务应明确显示等待，而不是偷偷把目标或数据搬上云。

## 3. ACP 负责会话，MCP 负责用工具

1. **ACP 是会话面。** Hub 选择绑定的主管、持久化消息、把用户回合与内部事件（任务完成、计划触发等）分开编排；Agent 决定怎么回答和调用哪些工具。适配器把增量、最终输出和取消映射到 Hub。Node 自己通过 ACP 与执行 Agent 交互，不跨公网做逐步执行 RPC。第一方 Agent 也走同一契约，不享有内置特权。
2. **MCP 是业务能力面。** 首版用 ACP v1 stdio；通过 `session/new` 的 `mcpServers` 注入受限的 MCP stdio 工具桥，先串通 `memory_search`、项目元数据和 `task_create`。API 与工具复用同一领域服务和校验，不从自然语言或 ACP 增量里猜测写操作，不把项目元数据接口当成宿主文件读取接口。不要求远程 ACP 标准传输、HTTP MCP、会话加载或系统提示扩展才能交付本地首版。混搭可接 Sous 的受认证适配器，让目标 Agent 继续走 ACP stdio，不要求第三方裸露公网端口。
3. **角色不是权限。** Hub 按绑定代次、实例、回合和作用域发放可撤销的最小工具权限，绝不发管理凭据或复用 worker 的 `sous mcp` 身份。审批政策和状态归 Hub，Agent 可提建议但不能因为是主管就批准自己的请求。第三方的内置 shell/文件工具不会因接 ACP 自动消失；必须实测限制工作区、宿主环境、凭据和自带工具。提示词、空目录和权限回调不是隔离；握手成功但权限不合格的 Agent 不能作为主管。
4. **换大脑不搬数据。** 先探测新 Agent；失败保留旧主管。成功后在回合边界停止旧绑定接单，等待收尾或明确取消后撤销旧工具凭据，拒绝迟到输出或写入；远程还校验 Hub 任期。项目 ID、对话、记忆、任务、审批、队列和在执行的 Run 保留。新主管拿到角色说明、线程摘要与近期上下文并可查 Hub；不承诺迁移 ACP 私有 `sessionId`、模型隐含状态或供应商私有历史。检索与整理由 Agent 调用 Hub，长期记忆作用域、固定项、来源和归档仍归 Hub，记忆规格改造不是切换主管的前置条件。
5. **明确降级。** 无主管时仍能操作历史、记忆、项目、审批和任务，AI 回合标明待处理；无 AI 审批/验收、摘要或巡检能力时，分别走人工、结构化上下文加近期消息、确定性巡检，不能暗用内置模型。无 Node 时仍能聊天/规划，执行任务排队或提示没有合适机器。幂等重试先查已有业务效果，不因断线重跑有副作用的请求。

## 4. 可选云工作机：计算按需，成果持久

**常在线的是云 Hub；按需启停的是云 Node 算力，不是主管或 WebUI。** 用户在所有个人电脑关机时仍可用手机访问云工作区、创建/审批任务，并运行**允许上云**且依赖材料可获得的任务。云工作机可由 VM 或其他合格隔离运行时承载；首版建议每工作区一台可复用的隔离 Linux 执行环境。不把可选云工作机变成常驻桌面、通用远控、跨云编排或本地项目兜底。

- **启动条件**：Hub 先检查执行目标、任务依赖、项目和凭据的上云授权、启动前审批、配额，再持久化任务及启动意图。有可执行任务选中云目标才启动或复用；浏览页面、聊天、建草稿、等前置审批或等指定本机均不触发。云控制器只负责资源生命周期，Agent 没有云管理凭据。
- **尽快可运行**：用预构建镜像带 Node、执行 Agent 和通用工具；短时注册凭据、探活通过后绑定实例代次，按授权加载项目和凭据，再派发。区分「排队」「启动云工作机」「准备项目」「执行中」「启动失败」。超时或失败保留任务、有限重试、提供取消和原因。先测启动、项目准备和首进展的耗时，不预建常驻热池。
- **空闲释放**：没有待执行工作、在途 Run 或临时保活授权时开始空闲计时；**5 分钟是待实测的初始参数**。运行中的审批等待不等于空闲；先安全收尾或按明确期限取消，不透明休眠进程。排空时来了任务，能停止回收则复用，否则排队唤醒新实例。计算释放前要确认可恢复状态已落地。
- **成果不跟算力一起删**：Hub 持久化业务和进度；未提交改动、用户文件及任务产物进入独立持久存储或 Hub 管理的可恢复产物。落地失败保留必要现场、告知原因和费用，不假装回收成功。存储保留期、删除、费用与计算分开；内存和临时缓存不保证恢复，凭据在重建时重新发放。
- **可恢复和幂等**：启停、注册与派发按工作区、实例/派发代次对账；处理重复事件、控制器重启、异常实例与旧连接；一个 Run 只接受有效代次。副作用不明先核对，不重放命令假装恢复。设置配额、启动/运行上限和回收保护。

## 5. 本地 microVM：让云 Hub 无法扩大宿主权限

这里的失陷假设只指**云端 Hub**；不把已经失陷的宿主 OS 或本地管理员纳入承诺。本地 Hub 是否也入沙盒独立决定，但如果它接收云指令，不能成为绕过隔离的宿主代理。远端可请求一个 Run，不能因此任意读取、删除或修改宿主文件。可执行的 **Node、Agent、终端、Git、搜索和项目文件工具在 Guest**；宿主只运行可信的窄权限组件来接任务、检查本机授权和管理 VM，不能把既有 daemon 整体视为这个薄组件。

1. **授权实际位置，不搬进固定根目录。** 用户在本机系统选择器中明确选择任意有权访问的项目位置、目录或单文件，记录真实位置、文件范围、用途、期限和本地授权主体。云端只获得不透明 `project_grant_id`，不能直接传宿主绝对路径、挂载参数或宿主 shell 请求。macOS 可评估 App Sandbox 和 security-scoped bookmark；存了 bookmark/授权记录不等于持续共享。默认不过度授权 home、系统路径、上级目录、密钥和环境文件；不转发 SSH agent、宿主环境或通用 socket。路径验证要覆盖外向符号链接、Windows junction/reparse point、嵌套挂载、目录替换、Git worktree 的外部 `.git` 引用；不能因项目结构复杂就扩大授权。
2. **每个 Run 都有最小、短时的访问窗口。** 默认本机逐次同意；离家后无人值守需要本机事先开特定项目的限时权限。持久授权不等于持续连接目录；接受 Run 时才打开，任务结束、取消或到期即收回。期限由宿主计时，云端无法续成无限权限。断线、Guest 卡死、宿主组件崩溃重启均要有宿主侧兜底；撤不掉就终止 VM 并确认发布目录的服务已结束。没有合格隔离后端，不开云端控制，不回退裸跑。
3. **首版从副本起步。** 快照/显式文件导入 → Guest 内可写 → 本机审 diff → 仅经用户批准写回，宿主有并发修改时报冲突而非覆盖。执行许可、读取、写回分开。实时联动/大仓库是后续动机；先考虑短时宿主强制只读，再独立授权实时读写；验证已打开句柄的宿主撤权，不把 Guest `umount`、VM 暂停或异常退出当成功。一个 Run 一个临时执行环境，不跨项目共用包含数据的 VM、分支和快照；预热只能用不含用户材料的基底。停止后清理挂载和临时材料，明确哪些用户批准的产物可以保留。
4. **接入通道不是联网许可。** 宿主主动连接该工作区 Hub 或 Relay，不对公网开本机端口；通过窄范围、可审计的本机通道（例如经实测可用的 Microsandbox 宿主–Guest 通道）把任务和结果交给 Guest，不暴露通用代理、宿主管理 API 或网络邻居。Guest 默认不通公网与宿主 LAN；必须访问的模型或依赖按本机策略放行。有批准的模型输入、结果和日志仍可能离开设备，**只读能保护原件，撤销能阻止后续访问，都不能追回已读或已上传数据**。
5. **覆盖所有旧旁路。** 当前 `run.go` 在 `ws.Dir` 启动 Agent 并接触宿主环境；`project_files.go` 有宿主直读/列表/搜索；`daemon.go` 处理远程管理、更新和工作区移除。迁移时还要覆盖终端、Git、文件预览、配置、维护和清理，保留现有系统的验证与签名语义，不允许云指令直达宿主管理面。

### 选型决定与历史调研

**2026-11-20 用户决定：Microsandbox 是本地 Node 首版唯一的沙盒后端。** 原先的 SmolVM / Microsandbox 比测计划改为直接验证 Microsandbox；SmolVM 仅留作调研记录，不实现、不作为自动回退。Terrarium 仍不纳入，Docker 不作为运行依赖；使用 OCI 镜像不等于依赖 Docker。此决定不选定云工作机运行时，也不意味着本地 Hub 必须入沙盒。下表保留此前从官方文档与源码核查到的信息，未安装实测。

| 候选 | 讨论结论 |
|---|---|
| **[SmolVM](https://github.com/smol-machines/smolvm)** | Apache-2.0、独立 Linux 内核；Apple Silicon、Linux KVM、Windows x64 WHP；Intel Mac 未见受测发行版。默认关网，可限制出站。固定 [v1.35.3 的挂载实现](https://github.com/smol-machines/smolvm/blob/v1.35.3/src/attach.rs) 中，运行时目录可热加、宿主侧强制只读、撤下共享设计覆盖已开文件；但先请求 Guest 卸载，Guest 无响应时不能假定已完成宿主撤权，Windows 也要单独实测。挂载对同 VM workload 可见、分支继承，不应用于多项目共用。上游 [`:staged`](https://github.com/smol-machines/smolvm/blob/v1.35.3/docs/volumes.md) 会在同步/正常停止时镜像写回，可能覆盖或删除原件，不能用作 Sous 默认副本模式 |
| **[Microsandbox](https://github.com/superradcompany/microsandbox)** | Apache-2.0、有 Go SDK；目录可只读、支持单文件挂载；Apple Silicon、Linux KVM，Windows WHP 在所读文档中标为预览。挂载随沙盒配置保存，选一次性 VM 时要销毁，不能把停止再启动当撤权。未核实同等的宿主运行中句柄撤销；[网络文档](https://docs.microsandbox.dev/sdk/go/networking) 说明拒绝网络仍可使用内部 Exec/FS 通道，Sous 所需能力按平台验证 |
| **Terrarium、Quicksand** | Terrarium 有独立轻量 VM 和默认无共享的设计，但用户明确暂不考虑。Quicksand 有 Python/QEMU 与动态 CIFS 挂载，增加分发和 SMB 撤销语义的验证成本，不在优先范围 |
| **Kiri、Gondolin、BoxLite** | `libracoder/kiri` 是轻量 Docker Desktop 替代，常规容器共享环境、Linux 可用宿主内核、Windows 走 WSL2；不是本需求的每 Run 独立 VM 授权模型。Gondolin 的可编程只读/隐藏文件有参考价值；BoxLite 的 Windows 路线引入 WSL2 + KVM，不优先。普通 WSL 默认自动挂载固定盘，不能直接当授权边界 |
| **系统原生 / 进程沙盒** | Apple Virtualization.framework / `vfkit` 可作 macOS 原生参考；Apple `container` 有系统/架构要求且其 machine 家目录共享默认值不能照搬。Windows Sandbox 是 Windows Guest，并有版本限制。Linux bubblewrap 可作为附加约束，不替代独立 Guest 内核。首版不自研维护三套后端 |

此前调研只查隔离、共享目录和生命周期的官方文档、开源仓库和源码，没有访问攻防论坛；后续也按这个范围验证。Microsandbox PoC 测发布兼容、安装签名/分发、硬件要求、冷启动/项目导入、稳态资源、销毁、关闭网络后控制通道，以及 Windows 上任务退出后的资源和授权清理；不把上游裸 VM 性能宣传当 Sous 实测。

## 6. 网络：少跨区、少往返，按路径测量

- **拓扑默认是星型。** 对一个工作区，浏览器/桌面或外部 MCP 客户端只接该工作区入口，Node 主动接各自 Hub，Node 之间不转发。WebUI 静态资源可单独走 CDN，业务 API 与流式事件不必再经过前端应用服务器。保留所需的配对、Passkey、授权、加密及租约语义；不叠加多余业务中继，也不为省一跳跳过这些边界。现有 Relay 在纯本地不必装；托管是否复用现有 Relay 需要实测和接入验证。
- **默认部署近，混搭付客观代价。** 第一方主管和云 Hub 优先同机分进程或同区域私网，数据层就近，云工作机默认同区域。每工作区先绑一个主区域，按用户/执行环境/模型路径和数据驻留选择；托管 Relay 尽量靠近 Hub，家庭 Hub 场景看实际线路。首版不做跨区状态复制、自动直连/Relay 切换。一次交互经过一个 WAN 入口不等于每次工具调用也要绕公网：假设 100 ms RTT，6 次必须串行的远程工具调用仅网络就约 600 ms，未含模型。
- **程序要减少等待，不削弱权限。** 先持久化再确认，异步开回合和派发；复用 WebSocket 和 Node 可靠通道，流式增量不逐段等确认或落盘，耐久事件按 `/ws?since` 恢复，Node 序号/ACK/重发去重，断线不重做副作用。对同作用域、无依赖的元数据按需组合，执行计算和文件操作就地做。大 diff、附件及日志不能堵审批/取消/聊天；限速、限队列，需要时分流。检查连接保活、代理超时与缓冲，不让增量攒成大段。
- **靠部署和配置消掉不必要的路程，按证据扩容。** 同机/同区域部署能少绕路；选择合适入口与反代能消掉额外跳数、重连或缓冲；更大服务器只解决 CPU、I/O、连接容量和排队瓶颈，不能缩短物理 RTT、供应商响应时间或让离线电脑出现。聊天状态要区分「已保存」「首段正文」「完成」；任务状态区分「等待设备」「启动环境」「准备项目」「执行中」。暖连接、模型响应、弱网重连、VM 和项目冷启动分开统计 p50/p95。
- **拟议基线，不是 SLA。** 用相同假 Agent 分别测本地、同区、约 80/180 ms RTT 与抖动；测无工具聊天、串行多工具、派发/审批/取消、大 diff 并发和断线重连，再以真实 Agent/模型复测。关联 `message_id` / `turn_id` / `run_id`，分别量 Hub 保存/排队、工具 WAN 次数、首段模型输出及增量送达、Node 接收、VM/项目就绪和首进展。建议暖连接、80 ms RTT 下保存确认 p95 ≤ 300 ms 作为第一条内部目标；不含模型和人工等待，其余目标由实测定。

## 7. 落地边界与仍需拍板的事项

**保住现有业务，逐步抽离，而不是推倒重来。** 现有 Hub 在 `hub.Open` / `RunOn` 装配并启动模型与主管；主管代码也夹有消息、上下文和 HTTP 职责。审批/验收、巡检和摘要还有独立模型依赖。先复用现有事件与持久化、任务/审批领域、ACP、`sousmcp` 和 Node 协议，做可选的旧主管适配器；走通本地可更换及托管路径后再退役。现有 Desktop 打开配置页面，随包网页是配对兜底，旧 daemon 依赖 Relay；真正的本地 App 要有完整 WebUI、本机身份和生命周期装配，不能把 localhost 当认证，也不是复制静态文件就完事。

**明确暂缓**：全组合首日发布、通用插件框架、自动跨 Hub 迁移/双主、第三方 Agent 任意接公网上的控制端口、跨区容灾自动切换、透明续跑内存、常驻云桌面、无条件实时读写挂载。哪些混搭进入推荐方案，按可用性、端到端延迟和真实用户场景逐项决定。

**留给 PoC/评审**：固定 Microsandbox 版本和集成方式，验证首发支持平台，尤其 Windows 和 Intel Mac；确定无公网时的 Guest 控制通道、文件导入删除规则和后台授权 UX；确定云计算/持久存储产品、区域、费用/配额和保留期；确定托管入口是否复用 Relay、远程主管和专用外部 MCP 接入方案；确定是否沙盒化本地 Hub；给首段正文、冷启动、断线恢复和大项目准备设实测目标。不将未测假设写成承诺。
