# 0025 主管的闭环：任务进展叫醒主管，子 agent 能问能报

- Status: Accepted
- Date: 2026-11-07

## Context

主管像一个“只能写任务单、只在用户说话时醒来”的经理：

- 任务完成的汇报是一条助手消息，不会叫醒主管。主管只在用户下次说话时才读到，所以“测完就部署”这类下一步不会自己发生；受阻和失败要 4 小时后才跟进。
- 汇报是 agent 的总结截到 800 字，没有“验证了什么、还剩什么、要谁决定”。
- 子 agent 不能提问，也不能报进度，拿不准时只能猜。
- 返工和重试都开新会话，前一轮的上下文丢了。
- 运维任务对服务器只是“偏好”：项目不在任何服务器上时悄悄派到了开发机，主管不知道，开发机上的 agent 只好用 ssh 部署。服务器上也没办法放项目（`project_clone` 只能 clone 到开发机）。

用户的原则是“条条大道通罗马”（0022）：不写死路径，由主管按场景选，但要让它知道走的是哪条路。

## Decision

1. **任务进展叫醒主管。** 任务引擎每发一条汇报（完成、失败、受阻、等验收、git 结果），以及依赖的任务失败、派不出去、派到了非偏好的机器时，在任务的对话里追加一个 `trigger.fired`（kind `task`，以【任务进展】【任务受阻】【任务在等机器】【任务派到了别的机器】开头）。主管决定接着推进、`notify` 用户，还是 `stay_silent`。
   - 合并：kind `task` 的触发等 20 秒（`Options.TaskBatch`）再开一轮，期间的进展一起处理；用户插话时立刻开始，并且也会看到这些进展。
   - 上限：自从用户上次说话起，一个对话只靠触发开的回合最多 8 轮（`MaxAutoTurns`），超过就静默停下，并在主线提醒用户一次。用户一说话就重新计数。没有另外按任务链计深度：回合上限已经挡住了互相触发的循环。
2. **结构化结果。** 工作 Run 的提示要求以“## 结果”一节收尾（做了、改动、验证、没做完 / 风险、需要决定）。Hub 解析它（`task.ParseResult`），汇报里显示这几项，解析不到时退回截断的总结。Node 的总结保留结尾 4000 字（原来保留开头，会把结果一节截掉）。主管多了 `task_result`，可以看完整的总结、diff（可以只看一个文件）和执行过程。
3. **子 agent 的通道：`sous mcp`。** Node 给每个工作 Run 的 agent 会话配一个 stdio MCP 服务（ACP 的 `mcpServers`），它通过 daemon 的本地 socket 和这个 Run 对话，凭每个 Run 的随机令牌：
   - `report_progress`：在 Run 上记一条“进度：…”。
   - `ask_supervisor`：发 `run.ask` 给 Hub，叫醒主管（【agent 的问题】）；工具调用一直等到下一条追加指令（主管的 `run_message`，或用户在任务页上的追加指令）作为回答，最多 20 分钟，等不到就让 agent 按自己的判断继续。每个 Run 最多问 3 次。
   - `report_result`：交结构化结果；总结里没有“## 结果”时按它补上。
   - 这个服务只能发文本，不读文件、不执行命令。node.json 的 `sous_mcp` 可以换启动命令或关掉（`["off"]`），只能在本机改。不支持 MCP 的 agent 照常工作，只是没有这三个工具。
4. **返工接着原来的会话。** 下一轮落在同一台机器、同一个 agent，而且上一轮记下了会话 id（工作 Run 结束时上报 `session_id`）时，`run.start` 带上 `resume_session` 和简短的 `continue_prompt`（只写新的要求：验收意见、上一轮的错误、被拒绝的操作、当前的任务说明）。接不上会话就发完整的提示。
5. **路由仍是偏好，但会说出来。** 不加“运维任务只能派到服务器”这样的硬规则。router 退回非偏好的机器时在 `Choice.Note` 里说明，写进任务状态、`task_create` / `task_dispatch` 的结果和【任务派到了别的机器】。工具结果写明任务在哪台机器上由哪个 agent 执行。
6. **服务器也能放项目。** `project_clone` 写明机器时可以 clone 到设了工作空间的服务器；不写机器时仍只挑开发机。服务器的环境说明里也写出“没有设置工作空间”。
7. **ssh 到已接入的机器：提示，不拦。** `ssh` 仍是硬信号，交给用户审批（安全规则不变）。Hub 从机器名、主机名、`hello.addrs` 和连接的来源地址认出目标是另一台已接入的机器时，在审批说明后面加一句“也可以让主管把这件事直接派到那台机器上做”。
8. 主管和其他角色用什么模型，在模型设置页由用户决定（0016），这里不改默认值。

## Alternatives

- **运维任务只能派到服务器**：路径固定，从开发机 ssh 部署、走 CI 等合法的路都被堵死，用户否决。
- **ssh 到已接入的机器一律拒绝**：同样是写死路径；现在只给提示，由用户决定。
- **主管在一轮里等任务结束（`task_wait`）**：会占住对话的 worker，用户插话要排队，还要处理超时；改用事件叫醒。
- **Node 解析结果并新增 `run.result` 字段**：要改协议和迁移；Hub 从总结里解析就够了，`report_result` 也落到总结里。
- **服务器单独的 `deploy_root`**：服务器本来就能设工作空间，复用它就够了。
- **`ask_supervisor` 用暂停 Run 实现**：暂停会取消 agent 当前这一轮，工具调用也随之中断；让工具调用等着回答更自然。

## Consequences

- 每个任务结束多一次主管调用（合并窗口和回合上限控制成本）。
- 主管的系统提示多了几行，`supervisor/context_test` 的窗口相应调大。
- 数据库多了 `runs.continue_prompt`（迁移）。
- `sous mcp` 需要真实 agent 实测（Claude Code、Codex、OpenCode、Kiro、Cursor 对 ACP `mcpServers` 的支持）；测试里由假 agent 的 `ask` 模式真的启动它。
- 子 agent 等回答时 Run 一直占着机器的并发槽位，最多 20 分钟。
