# 0022 灵活优先：去掉固定流程，交给主管判断

- Status: Accepted（第 1 条“只和主管对话”被 0028 修改）
- Date: 2026-11-06

## Context

sous 里有不少写死的流程和默认值，不符合用户的实际习惯：

- 代码任务固定走“worktree → 验收 → push + PR”（0009），做完就提交；但不是每个项目都有 git，不是每个任务做完都要马上提交，个人项目也不想走 PR。
- 新任务的起点分支按“指定 → 远端默认分支 → 当前分支 → main → master”的顺序挑（`workspace.startPoint`），而且基于 `origin/<分支>`，会忽略用户本地没推送的提交；用户的本意通常是“当前分支”，但这同样不该预设。
- 任务分成代码、一般、运维三种，每种绑定一整条流水线和机器角色，就地在开发机上跑脚本、在没有 git 的目录里改东西都没有合适的类型。
- 每个代码任务和一般任务都必须经过 reviewer 模型验收，不通过就自动返工；reviewer 只看 diff，跑不了测试。
- 新建项目默认用 wokspace 结构。
- 主管看不到项目文件，想讨论需求只能派一次性的任务，子 agent 跑一轮就结束，没法连续对话。

## Decision

原则：**灵活优先**。流程交给主管按场景判断，拿不准就问用户，问过的答案记成这个项目的习惯；**安全边界保持确定**（权限模式、底线规则、硬信号、服务器的严格本地策略、审批上限，即 0005、0010、0014 的服务器策略、0019），不交给模型判断。

1. **只和主管对话。** 讨论还是派活由主管判断：问题、想法当作讨论；明确的指令且范围清楚才建任务；拿不准按讨论处理，讨论收敛时主管提议拆成任务，用户确认后派发。
2. **项目顾问会话。** 主管通过 `consult` 向一个项目的常驻只读子 agent 提问：它在开发机的项目目录里运行，只能读，会话长期保留（空闲时退出进程，来问题时恢复）。顾问的回答原样显示在对话里，主管不转述。简单问题主管用 `project_read` 自己读文件。
3. **任务由几个独立属性组成，不再按类型套流水线。** 在哪儿做（worktree 分支 / 就地 / 临时目录）、哪台机器、要不要验收和由谁验收，由主管建任务时按场景填写。“代码 / 一般 / 运维”只作为显示标签。服务器上的严格策略跟着机器走，不跟着任务类型走。
4. **验收是主管的工具，不是必经阶段。** 主管决定验不验、谁来验（reviewer 模型、审查岗位的 agent 实际跑测试、交给用户）、不通过时怎么办（返工或问用户）。返工次数仍有硬上限。
5. **任务只管做事，git 操作是单独的工具。** 任务结束在“完成，改动在某个分支上（或就地）”。提交、合并、推送、开 PR、撤回由主管按用户的话执行（`git_commit`、`git_merge`、`git_push`、`git_pr`、`git_undo`），不论单人还是多人项目。Node 只执行写死的命令（0002、0012）。复杂操作派 agent 去做。sous 可以合并，也可以推送任何分支，按权限模式审批；底线只有一条：不对受保护分支 force push。
6. **分支、目标和时机都不预设。** 起点分支、合并目标、要推送的分支是工具的必填参数，Node 不再按顺序自己挑。主管根据 checkout 的实时状态（当前分支、上游的领先和落后、未提交的改动、detached）和对话判断，拿不准就问。用户的说法第一次有歧义时问一次，记住答案。
7. **新建项目不默认任何结构。** 用户说了或有记下的习惯就照做，否则问。
8. **部署的触发改成“部署分支有了新提交”**，不再只靠查 PR 是否合并（取代 0014 里“合并后自动部署”的做法）。部署分支是项目的显式配置，没有默认值。

0009 被本记录取代。

## Alternatives

- **项目级的 git 模式（none / solo / team）加固定交付路径**：比一刀切好，但仍然是预设；用户的习惯是“我说推送就推送、说 PR 就 PR”，与项目是不是多人无关。
- **对话里加模式切换（sous / 讨论），讨论直接和子 agent 对话**：能连续讨论，但要用户自己切模式、选项目，还容易搞混在跟谁说话。主管看得到代码以后就不需要模式了。
- **主管转述顾问的回答**：慢，会丢细节，上下文里内容存两份。
- **个人项目不用 worktree，直接在主目录改**：简单，但同一个项目不能并行；改成“在哪儿做”这一属性，由主管按场景选。

## Consequences

- 主管的判断变多，提示词要写清楚判断方法和“拿不准就问”；判断错的代价靠两点兜住：每次 git 操作都用一句话报告；没推送的合并和提交能撤回。
- 任务表多出属性（在哪儿做、验收方式、起点），`task.Create`、`Advance`、`review`、`route` 都要改；`PurposeDeliver` 和自动 rebase 去掉，冲突处理移到 `git_merge`。
- worktree 的生命周期改成跟着分支走：分支合并或丢弃后再清理，而不是任务一结束就清理。
- Node 多出只读档位的策略、顾问会话的空闲和恢复、git 操作和 checkout 实时状态的接口；`docs/api/core-hub-node.md`、`docs/api/core-hub-http.md` 要更新。
- 没有 git 的目录用影子 git（`GIT_DIR` 放在 `~/.sous` 下）做快照，供看 diff 和撤销，项目目录里不多出 `.git`。
- 实现见 `work/specs/flexible-workflow/`。
