# 远程管理机器上的 agent：需求

状态：已确认范围并实现（2026-11-04）。R2.5 不加 Gemini CLI；远程管理默认开启；只做机器级默认模型。

## 背景

现在机器配对后，“机器”面板只显示已安装 agent 的版本和登录状态（`internal/agents.Detect`）。没装的 agent 不显示；没登录、想换模型、想改 agent 自己的配置，都只能到那台电脑上手动操作。模型只能通过 `node.json` 的 `agents` 覆盖启动命令来选（比如 Cursor 的 `--model auto`）。

目标：机器连上 Hub 之后，在 PWA 里就能把这台机器上的 agent 配好、装好。

## 需求

### R1 查看
- R1.1 “机器”面板列出 sous 支持的全部 agent，包括没安装的，每个显示：是否安装、版本、登录状态、当前默认模型和思考强度。
- R1.2 可以手动“重新检测”一台机器，不用等 10 分钟一次的清单上报。

### R2 安装
- R2.1 没安装的 agent 旁边有“安装”按钮。安装方法由 sous 内置（每个 agent、每个系统一条官方安装命令），用户确认后在那台机器上执行。
- R2.2 安装过程的输出实时显示在页面上，结束后显示成功或失败，并自动重新检测。
- R2.3 已安装的 agent 可以“升级”（同一条安装命令，或 agent 自带的 update 命令）。
- R2.4 缺少前置条件时（例如 Claude、Codex 的 ACP 适配器需要 Node.js / npx），页面说明缺什么。
- R2.5 支持 Claude Code、Codex、Cursor、OpenCode、Kiro CLI；不新增 Gemini CLI（先把现有的体验做好）。

### R3 登录授权
- R3.1 未登录或状态未知的 agent 旁边有“登录”按钮，在那台机器上启动 agent 自己的登录流程，优先用不需要本机浏览器的方式（设备码、复制链接）。
- R3.2 页面显示登录命令的输出，把其中的链接和验证码突出出来，可以点开或复制；需要回填验证码时，页面上能输入一行文字发给登录命令。
- R3.3 可以改用 API Key 登录：为某个 agent 设置环境变量（如 `ANTHROPIC_API_KEY`、`OPENAI_API_KEY`），只保存在那台机器上，Hub 和页面都不回显明文。
- R3.4 可以“退出登录”（agent 有对应命令时）。
- R3.5 登录完成后自动重新检测登录状态。

### R4 模型与思考强度
- R4.1 对每个已安装且已登录的 agent，页面能列出它通过 ACP 报告的可选模型、思考强度以及其他会话选项（ACP `configOptions`，category 为 `model`、`thought_level`、`model_config`）。
- R4.2 用户为每台机器、每个 agent 选一个默认值，之后在这台机器上新开的会话都用它。
- R4.3 agent 不支持这些选项时，页面说明原因，并引导到“编辑配置文件”。

### R5 编辑原始配置
- R5.1 每个 agent 可以打开它的配置文件（内置路径列表，如 `~/.claude/settings.json`、`~/.codex/config.toml`），在页面上编辑并保存。
- R5.2 也可以编辑这台机器的 `node.json`，但设备令牌不显示、不能改。
- R5.3 保存前校验格式（JSON / TOML），格式错误不写入；文件在打开后被别人改过时提示冲突，不覆盖。
- R5.4 每次写入前在原文件旁边留一份备份。
- R5.5 `node.json` 改动后不用重启 daemon 就生效（正在执行的 Run 不受影响）。

### R6 安全
- R6.1 这些操作都只对已登录 sous 的用户开放（现有的 passkey 会话 + CSRF）。
- R6.2 安装、登录、改配置都写进 Hub 的事件日志（谁、哪台机器、做了什么），但不记录密钥和文件内容。
- R6.3 每台机器可以在本地 `node.json` 里关闭远程管理（`remote_admin: false`），关闭后这些请求在机器上直接拒绝，远程也不能把它重新打开。
- R6.4 只能读写内置列表里的文件，不能指定任意路径；只能执行内置的安装和登录命令，不能执行任意命令。

## 不做

- 网页终端（任意命令的远程 shell）。
- 按任务或按 Run 单独选模型（以后可以在 `run.start` 里加字段，本期只做机器级默认值）。
- 把密钥放进系统钥匙串（沿用 `node.json` 0600 的做法，和设备令牌一样）。
