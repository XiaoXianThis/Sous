# web

- Purpose: sous 的 PWA 前端：聊天、任务、审批、机器与设置界面。手机、平板、浏览器直接用；构建产物同时被 desktop 内嵌。
- Stack: React 19 + TypeScript + Vite 6 + Tailwind CSS 4（设计变量在 `src/app.css`，映射成 `bg-page`、`text-ink` 等类），Vitest；`react-markdown` + `remark-gfm` + `highlight.js`（聊天的 Markdown）；PWA（手写 Service Worker 和 manifest，见 `public/`；主屏图标是 `apple-touch-icon.png`（180px）和 `icon-192.png` / `icon-512.png`，由 `icon.svg` 去掉圆角渲染而来，因为 iOS 不认 SVG 图标）；`@xterm/xterm`（机器上安装、登录 agent 时的终端）；`@radix-ui/react-dropdown-menu`（需要自动避让边缘的菜单，如 `ModelSwitch`：模型列表 + 思考强度二级菜单，渲染在 portal 里，层级 `z-[60]`，打开时锁定 body 滚动）。
- Depends on: core 的 `docs/api/core-hub-http.md` 契约。构建产物 `build/web/` 由 core 的 Hub 托管（运行时读取），也被 desktop 消费。

## Conventions

- 使用 bun 运行前端 CLI（`bun install`、`bun run`），锁文件是 `bun.lock`（由 `package-lock.json` 迁移，CI 与本地都固定 bun 1.3.14）。
- `bun run dev` 在 5173 端口启动，把 `/api`、`/ws` 代理到 `SOUS_HUB`（默认 `http://127.0.0.1:8787`，先 `wok dev core`）。也可以 `wok build web` 之后直接打开 Hub 的 8787 端口。
- 状态变化写成纯函数放在 `src/lib/reduce.ts`，并配上 `*.test.ts` 单元测试；组件里不写事件处理逻辑。
- 共享状态在 `src/lib/app.ts`：`chat`、`ui`、`wb` 是可变的 store。改完字段后必须调用对应的 `emit()`，组件用 `useChat()` / `useUi()` / `useWb()` 订阅；不调用 `emit()` 的修改不会重绘。
- 构建时 `vite.config.ts` 写出 `build-info.json`（commit、是否有未提交改动、构建时间），并把同样的信息定义成 `__BUILD__`；Hub 的 `/healthz` 和设置页的“版本”据此提示旧构建。首包只放 React、图标和 Markdown：设置、项目对话框、终端日志用 `lazy()` 加载，`highlight.js` 在第一次出现代码块时才加载（`Markdown.tsx` 的 `useHljs`）；新加的大依赖也要这样分出去。
- 状态词统一用 `src/lib/status.ts` 和 `src/lib/tasks.ts` 里的词表（待整理、待开始、排队中、执行中、等你审批、验收中、受阻、失败、已完成、已取消），不要在组件里另写一套。数字旁边要有文字（工作台统计、卡片底部计数），不能只靠悬停提示。
- 次要文字的颜色（`--muted`、`--faint`）在浅色和深色下都要对背景有 4.5:1 的对比度；页面允许缩放（不要在 viewport 里加 `user-scalable=no`），iOS 聚焦放大靠输入框 16px 字号避免。
- 界面只做中文。中文输入法组合输入时（`isComposing`）按 Enter 不能发送消息。
- 配色参照 Cursor 主题（开源复刻 BioHazard786/cursor-theme-vscode）：灰色是框架（`bg-rail`、`bg-chrome`：左栏、聊天栏、设置导航），近白是内容区（`bg-page`），白色是卡片（`bg-panel`），层级靠深浅和 1px 细线（`--line`）区分；整体只用黑白灰：状态色 `--warm`、`--danger`、`--ok`、`--done`、`--info` 都映射到灰阶（靠字重和深浅区分，`tone-*` 只改文字色，胶囊统一中性底），岗位头像 `c-<颜色>` 全部是同一种灰；唯一的彩色是天蓝 `--accent`，只用于主要按钮、选中态和特殊需求，链接色也是它。项目和任务的标题前不放图标。深色模式由 `src/lib/theme.ts` 写在 `<html data-theme>` 上（跟随系统 / 浅色 / 深色，存在 localStorage `sous.theme`；`index.html` 里的内联脚本在加载前先套上），深色变量写在 `:root[data-theme='dark']`，不要用 `prefers-color-scheme` 媒体查询。
- 颜色只用 `src/app.css` 里的 CSS 变量（Tailwind 主题映射成 `bg-page`、`bg-panel`、`bg-sunken`、`bg-hover`、`text-ink`、`text-muted`、`text-faint`、`border-line`、`bg-accent`、`shadow-card`、`shadow-soft`、`shadow-pop` 等），浅色和深色都要能看。
- 视觉语言是“客户端”而不是网页：卡片用阴影（`.card`、`shadow-*`）而不是边框，信息优先用图标 + 数字表达（`.pill tone-<语气>`），操作优先用图标按钮（`.icon-btn` 加 `aria-label` 和 `data-tip` 悬停提示，`data-tip-pos="bottom"` 放在下方），只有主要操作用带字的 `.btn`。
- agent 的图标在 `AgentIcon.tsx`（claude、codex、cursor、opencode、kiro、sous，未知的显示首字母）；“谁在干活”用 `Avatar.tsx` 的 `Who`：岗位头像带 agent 角标（`stack` 时并排），没有岗位时只显示 agent 图标。新增 agent 时在 `AgentIcon.tsx` 加一个标记。
- 工作台（`docs/architecture/workbench.md`，`work/specs/workbench-single-page`）：`Shell.tsx` 是左侧图标栏（工作台、对话开关、机器状态、深浅色切换、设置）+ 工作台 + 聊天栏；手机三个标签。工作台只有一页，只放项目卡片：顶部标题行右侧是几个图标加数字的概况（正在执行、要你处理、待办、机器在线），再右边是“+ 项目”；“要你处理”（待审批 + 收件箱里的任务）默认收起，点它的图标才弹出 popover；`#/inbox` 只是打开这个 popover。工作台上的任务行是两行高：标题和任务状态，下面是最近一次 Run 的状态（`CardTask.run` / `runLook`）和接手的 agent（图标 + 名称）；不画阶段进度条（进度条只在弹窗的任务详情里）。路由在 `src/lib/route.ts`（`#/`、`#/projects` 兼容旧链接、`#/project=<id>`、`#/task=<id>`、`#/inbox`），`Shell` 始终渲染 `Workbench`，`task` / `project` 决定顶层 sheet，`inbox` 只是打开“要你处理”popover。工作台数据是 `GET /overview` + `GET /inbox`（`wb.data`、`wb.inbox`），按 `tasksRev`、`nodesRev`、`inboxRev`、`runsRev` 去抖重拉；`run.output` 不重拉。项目卡片由 `src/lib/workbench.ts` 的 `projectCards` 计算（包含已归档的项目，`card.archived`；工作台只画激活的，“打开”按钮弹出 `ArchiveModal.tsx`，用 `archivedCards` 按 `touchedAt` 倒序和搜索过滤，卡片复用 `Workbench` 的 `renderCard`；归档 / 激活走 `src/lib/projects.ts` 的 `setArchived`），卡片右下角是 `src/lib/time.ts` 的 `ago(touchedAt)`（相对时间，工作台每分钟重绘一次），卡片排成等高的网格；卡片里有“任务 / 详情”两个标签（`ProjectTabs`，标签状态在 `Workbench` 里，卡片和弹窗共用），详情是懒加载的文件树 `FileTree.tsx`；点卡片上的放大按钮或树里的文件会打开 `ProjectModal.tsx`（从卡片位置长出来、关闭时缩回去的弹窗，`data-project-card` 用来找到卡片），弹窗里的 `FileEditor.tsx` 可以看和改文件（代码按扩展名高亮：`src/lib/highlight.ts` 注册语言并提供 `languageOf` / `imageType`，编辑区是透明 textarea 叠在高亮层上；Markdown 和 SVG 默认看渲染，可切到源码；图片用接口返回的 `data` 显示）（`GET/PUT /projects/{id}/file`，保存带 `base_sha256`，Cmd/Ctrl+S 保存）。圆角用 9 / 12 / 14 / 16 / 18 这一档（`--r-sm` `--r-md` `--r-lg`），`Icon` 会把尺寸吸附到 12/14/16/18/20/24 并统一描边粗细，列表项最小高度 64px，按钮 38px（small 32px）（`auto-rows-fr`，不是瀑布流）；任务只有 `todo/active/attention/closed` 四态（`status.ts`），详细状态只做 badge 文案。运行中 Run 的活动由 `src/lib/live.ts` 累积在 `wb.live`（100ms 合批），只有 `AgentCard.tsx` 读它；刷新时用 `/runs/{id}/log` 的尾部补最近输出。任务不再有单独的 sheet：`#/task=<id>` 会打开该任务所在项目的 `ProjectModal`，“任务”标签里左侧竖排列出项目的全部任务（`TaskRow`，`ProjectCard.listTasks`），右侧是 `TaskView embedded`（手机上列表和详情分页）；弹窗的显示由 `Workbench` 根据路由和 `open` 状态决定，项目 sheet 复用 `ProjectEditor`，Run sheet 用 `api.run` + live。图标在 `Icon.tsx`（Hugeicons 免费版 `@hugeicons/core-free-icons` + `@hugeicons/react`，按短名映射；新图标在映射表里加一行），岗位头像是 `Avatar.tsx`，Run 的计划和步骤列表在 `RunSteps.tsx`，颜色类 `c-<颜色>`、语气类 `tone-<语气>` 和组件嵌入规则 `.embed` 在 `app.css`。
- 话题（决策 0027）：`ChatView` 有话题和时间线两种视图（标题行的图标切换，存在 localStorage `sous.chatView`，默认话题；传了 `onSendIn` 才有话题视图）。话题视图是 `TopicList.tsx`：顶部“需要你处理”（`wb.inbox`，默认收起）、按 要你处理 / 进行中 / 已结束（折叠）分组的话题卡片、“更早的对话”（没有话题的旧消息）。卡片收起时显示标题、当前结论或最新一句、任务概况和未读点（localStorage `sous.topicSeen`）；展开时按需拉 `GET /threads/{id}/messages?topic=`，显示当前结论、任务（状态 + `TalkLog`）、消息（汇报收成一行，用户消息下显示“排队中 / 已看到”和“已从新话题并入 · 撤销”）和话题内的回复框。分组、排序、未回复、未读这些纯计算在 `src/lib/topics.ts`（有测试）；`reduce.ts` 按 Hub 的规则给实时消息补 `topic_id`（`topicOfEvent`），处理 `message.moved`、临时的 `message.seen`（`chat.answering` 是每个线程正在处理的话题，流式回复画在那个话题里）和 `topic.updated`，话题列表按 `chat.topicsRev` 去抖重拉。全局输入框发的消息开新话题，`send` 返回话题 id 后通过 `ui.openTopic` 展开它；`#topic=<id>`（推送链接）用 `openTopic` 打开，折叠的分组里也会显示。`TalkLog.tsx` 是主管 ↔ 子 agent 的沟通（`GET /tasks/{id}/talk`），默认收起，话题卡片和 `TaskView` 里都有。
- 主管自己的工具调用（消息的 `tools`，`message.tools` 事件由 `reduce.ts` 补上）由 `Message.tsx` 的 `SupervisorTools` 画在助手消息下面：默认折叠成一行“调用了 N 个工具”，点开用 `RunSteps.tsx` 的 `ToolList` 列出 工具名 · 参数摘要（· 失败：错误）；折叠状态不保存。它和 Run 的工具无关，不要放进 `RunChip`。
- 聊天里 Run 只显示成 `RunChip`，步骤在项目弹窗的任务详情里。`TaskView` 顶部（固定不随内容滚动）是标题，任务操作是标题行右侧的图标按钮（只有派发 / 重试是带字按钮）；底部固定一行（不换行，放不下横向滚动）是全部任务信息：状态、阶段（`StageBar inline`）、岗位、agent 和机器、在哪做、验收、分支和去向、PR、状态说明。下面是可滚动的执行记录（每个 Run 一张卡片（不画阴影和描边，底色比面板略深一点，四周 16px 内边距），按时间倒序，最新的在最上面）；等你验收或有 Run 在跑时，这一行下面再加“通过 / 要改”和给 agent 的补充输入。每个 `RunCard` 的计划、工具步骤、思考和原始输出收进“执行过程 · 时长”（`time.ts` 的 `duration`），默认收起；最后一个 Run 默认只显示提示词（两行灰字，不画气泡）和最终回复，更早的 Run 只显示标题行，点开才展开。审批不在聊天里出现（`RunChip` 只显示“等你审批”状态）：有要人工批的审批时，工作台上运行中任务的 `AgentCard` 把输出摘要那一格（36px）换成 `ApprovalCard.tsx` 的 `ApprovalStrip`（`size="slot"`；`AgentCard` 的根是 `div`，整卡点击靠垫在底下的透明按钮，避免按钮嵌套），任务行 `TaskRow` 原地变成 `ApprovalStrip`（高度不变，只给“允许这一次 / 拒绝”两个快捷按钮，`quickOptions`；点其余部分打开任务详情，那里的 `RunCard` 有完整的 `ApprovalCard`），答完变回去；`review: ai`（AI 审批中）的一律不显示。`RunCard` 里 agent 的思考和输出跟聊天一样画（`Message.tsx` 导出的 `Thinking`、`Markdown`），结束后的总结也是 Markdown。长内容（任务汇报、顾问回答、Run 输出和总结）用 `Message.tsx` 的 `Clamp` 限高折叠，带“展开全部”；卡片和消息的 grid 要写 `grid-cols-[minmax(0,1fr)]`，否则代码块会把卡片撑出去。设置是居中弹窗 `SettingsModal`（手机上全屏），点击外部不关闭，只能用关闭按钮或 Esc；含“外观”页切换主题。原来各自是弹窗的组件放进 `.embed` 容器后按页面内容显示（`app.css` 里 `.embed > .backdrop:first-child + .sheet` 的规则），所以这些组件的根节点顺序必须是“遮罩、面板”。
- 推送通知的链接是哈希路由（`#approvals`、`#task=<id>`、`#thread=<id>`），由 `src/lib/route.ts` 的 `parseRoute` 解析、`followHash` 处理（变成工作台路由）；Service Worker 在已打开的窗口里用 `postMessage({type: 'open', url})` 通知页面。
- 列表类视图（任务、首页“需要你处理”、待审批数）按 `chat.tasksRev` / `chat.inboxRev` 重新拉取；有新的事件类型会影响它们时，记得在 `reduce.ts` 里加上对应的计数。Run 结束或暂停会让它的待审批过期但不产生审批事件，所以 `run.ended`、`run.paused` 也要刷新首页。定时任务列表按 `chat.schedulesRev` 重新拉取。
- 聊天界面参照 ZCode（zai-org/ZCode 的 `DESIGN.md` 和 `ai-elements/message.tsx`）：助手消息不画头像和气泡，整宽显示 Markdown；用户消息是右侧的中性灰圆角气泡（`--user-bubble`），纯文本；悬停显示复制和时间；输入框是 16px 圆角、细边框、不发光，发送按钮是 `bg-ink` 的圆形。Markdown 由 `Markdown.tsx` 渲染（`react-markdown` + `remark-gfm`，不渲染原始 HTML；标题 `mt-6 mb-3`，列表 / 引用 / 表格 / 任务列表的样式写在组件里；代码块有语言、自动换行和复制按钮，用 `highlight.js/lib/core` 只注册常用语言，流式输出时不高亮）。链接色是 `--link`，行内代码底色是 `--code-inline`，高亮配色是 `app.css` 里的 `.hljs-*`。
- 对话的主体是 `ChatView.tsx`（标题行和对话选择、时间线、输入框），`ChatPanel.tsx`（右侧聊天栏，只列没有 `project_id` 的线程）和 `ProjectChat.tsx`（项目对话）都只是给它传线程列表和发送方式。`chat.threads` 里包含项目对话，按 `project_id` 过滤；`ui.projectThread[项目 id]` 是项目弹窗里显示的对话，第一次发消息时才建线程（`sendToProject`）；`openThread` 遇到项目对话会设置 `ui.openProject`，由 `Workbench` 打开那个项目的弹窗。
- 项目对话停靠在 `ProjectModal` 的右侧（弹窗加宽到 1560px），标题行的对话按钮开关它；每次打开弹窗都默认收起（手机上打开时盖住整个弹窗，顶栏最左边是 `ChatView` 的 `leading` 里的返回按钮）。弹窗桌面标题行只有一行（项目名、位置、标签、按钮），高 54px，和右侧聊天标题栏底线对齐。项目里选中的任务会作为 `context.task_id` 随消息发出。后端把项目对话的作用域限定在这个项目（见 `docs/api/core-hub-http.md`）。
- 宽度可拖动：`ResizeHandle.tsx`（8px 透明热区，悬停 / 拖动时显示 2px 强调色细线，方向键微调，双击还原）+ `src/lib/resize.ts` 的 `useStoredWidth`。右侧聊天栏写到 `.shell` 的 `--chat-w`（`localStorage` 的 `sous.chatWidth`，CSS 用 `clamp` 保证工作台至少 420px），项目对话是 `sous.projectChatWidth`。
- `kind: trigger` 的消息（定时任务、自动跟进）虽然 `role` 是 `user`，但不是用户输入的，显示成一行可展开的系统提示，不显示成用户气泡：两侧细线中间一枚胶囊（类型 + 一句标题 + 时间），标题和展开后的正文由 `src/lib/trigger.ts` 的 `triggerView` 解析，会去掉 Hub 写给模型的括号说明。`notice` / `report` / `inspector` 是带阴影的白卡片（彩色图标 + 标签 + 时间，复制按钮在卡片右上角）。思考过程（`Message.tsx` 的 `Thinking`）在模型还在思考时（`streaming` 且还没有正文）自动展开成限高的框，内部滚动并跟住最新一行，开始输出正文后自动收起；用户点过就以用户为准。
- 机器上的安装、登录作业：`agent.job.*` 事件由 `src/lib/jobs.ts` 累积成 `chat.jobs`（按字节 `offset` 去重，和 `GET /nodes/{id}/jobs/{job}` 的尾部合并），`JobLog.tsx` 把它写进 xterm，并从输出里找出链接和验证码。管理界面是 `AgentPanel.tsx`（从“机器”打开）和 `ConfigEditor.tsx`。
- 项目终端：`ProjectModal` 的第三个标签 `shell`（`ProjectTabs` 的 `shell` 属性，卡片上不显示，卡片把它当 `tasks`）。`ShellPanel.tsx` 管标签和选机器（`GET/POST /projects/{id}/shells`），每个终端一个 `ShellTerm.tsx`（xterm，输出来自 `chat.jobs`，按键 15ms 合批发 `job input`）；切走时保持挂载、隐藏，回来再 fit。打开遇到 401 `reauth` 时显示“验证并打开”，按钮里调用 `passkey.ts` 的 `reauthenticate()`（开发模式走 dev-login）——WebAuthn 要在用户点击里调用，不要在 fetch 之后自动弹。
- 模型：设置的“模型”页是 `Models.tsx`（角色的模型 / 思考强度、供应商增删改、读取模型列表、测试）；聊天标题旁的 `ModelSwitch.tsx` 直接切主管的模型和思考强度。选项值是 `provider_id + \u0000 + model`（`choiceValue` / `parseChoice`）。改供应商可能 401 `reauth`，按钮里调 `reauthenticate()` 再重试。显示成“跟主管一样”的角色（`inherited`）不要把主管的值当成自己的。

- 手机布局（≤760px，`src/lib/phone.ts` 的 `PHONE_QUERY` / `usePhone()`，和 `app.css` 的断点一致）走 iOS 26/27 Liquid Glass（决策见 `docs/decisions/0018-phone-liquid-glass.md`）：灰色分组背景（`--chrome`）上放无描边的白卡片，控件是浮在内容上的玻璃（`.glass`，材质变量 `--glass*`，浅色深色各一套）。`.glass` 的材质画在 `::after`、高光描边在 `::before`，元素自己要有定位；不要直接在元素上写 `backdrop-filter`，那样里面 `position: fixed` 的弹层会被困住（`.sheet` 同理，材质也在 `::after`）。圆钮 `.glass-btn`（44px，按下放大），多个操作放进一个 `.glass-group` 胶囊（里面用 `.phone-bar-btn`），带字的胶囊 `.glass-pill`。底部是悬浮的玻璃标签栏（`Shell` 的 `.tabbar`，滑动的 `.tabbar-lens`，标签栏始终展开；键盘打开或聊天输入框聚焦时隐藏）；设置是第三个标签：手机上 `SettingsModal` 是分组列表（`ui.settings === 'home'`，桌面把 `home` 当第一页），点进去 `.push-in` 推入，标签栏在它上面（`.shell[data-settings]`）。页面顶部是 `PhoneHeader.tsx`（没有底色，只有玻璃按钮：`leading` 放 `BackButton`，`actions` 自动放进玻璃胶囊；大标题滚走后出现渐隐，`fade` 指定渐隐成什么颜色）。聊天在手机上是 `.chat-phone`：顶栏和输入框都浮在时间线上，输入框是文字在上、工具和发送在下的玻璃胶囊，高度写进 `--composer-h`。项目弹窗在手机上是推入的全屏页，顶栏后退按钮一层一层退（项目对话 → 任务 / 文件 → 列表 → 关闭），Escape 也一样。弹出层用 `.backdrop` + `.sheet`（手机上是离边 8px、圆角 34px 的玻璃抽屉），不用桌面的 popover。数据和业务组件两端共用，只有页面外壳按 `usePhone()` 分开。
- 触屏行为在 `src/lib/ios.ts`（`installTouch()`，`main.tsx` 里装上；纯计算在 `gesture.ts`，两者都有测试）：拦掉双指缩放；`visualViewport` 写 `--vv-h` / `--vv-top` / `--kb` 和 `<html class="kb-open">`，`#root` 在触屏上按它定高，所以键盘不会顶起页面（底部固定元素用 `bottom: var(--kb)`）；`.sheet` 往下拖关闭（等同点前面的 `.backdrop`；从输入框、`.xterm`、`[data-no-drag]` 上开始的不算）；主屏 App / WebView（`html[data-standalone]`）里从左边缘右滑返回：点最上层 `[role=dialog]`（`position: fixed` 且可见）里最后一个可见的 `[data-back]`，没有就发 Escape；只想滑走一部分内容时把它标 `data-page`。新增弹层、返回按钮时按这套约定加属性。触屏上界面文字不可选、不弹长按菜单，要能复制的文字加 `.selectable`（`.md`、`pre`、`code`、输入框、终端已经可以）。触屏上所有元素 `overscroll-behavior: none`，不回弹。
- 设置页里打开的二级弹窗（机器 → agent 管理 → 配置编辑等）：设置页把自己的根 `Sheet` 压平进页面（`SheetPlaceContext` 为 `root`），其中再开的 `Sheet`（`nested`）用 portal 画到 `<body>`，否则会被设置面板的 `overflow-hidden` 裁掉，手机上还会被标签栏盖住；自带根节点的组件（如 `Machines`）要自己把 context 设成 `nested`。手机（≤760px）上 `html, body, .shell` 都是 `overflow: hidden`，页面不滚动，滚动只发生在内容区内部；键盘打开或聊天输入框聚焦时标签栏是 `display: none`（真隐藏，不是滑出屏幕）。
