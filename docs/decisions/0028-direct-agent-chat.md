# 0028 用户可以在项目对话里直接和子 agent 对话

- Status: Accepted
- Date: 2026-11-11

## Context

0022 定下“只和主管对话”，否决了“讨论直接和子 agent 对话”的模式切换，理由是用户要自己切换模式、选项目，还容易搞混在和谁说话。

实际使用中，有些话只想说给某个 agent 听：补一句它刚才漏掉的细节，问它为什么这样改，让已经做完的任务再小改一下。经主管转达既慢又会走样，还要多一次主管调用。现在只能在任务页发追加指令，而且只对正在运行的 Run 有效。

## Decision

主管仍然是默认的对话对象，用户可以绕过主管直接找 agent，但主管必须知道发生过什么。

1. 只在项目对话里开放。可以对话的对象有：这个项目里正在运行的 Run、已结束但留有会话的任务、项目顾问。主线不开放。
2. 对象一直显示在输入框上，对象不是 sous 时输入框换颜色，并写明“只有 X 会看到”。这回应了 0022 说的“搞混在和谁说话”。
3. 已结束的任务接着原会话开一个 `chat` Run，任务回到“进行中”；接不上会话时直接告诉用户，不退回新会话。
4. 私聊不叫醒主管，原文也不进主管的历史。主管的本轮环境里列出“用户和哪个 agent 私聊过几条”，需要时可以查看原文。私聊产生改动时，任务汇报照常叫醒主管（0025）。
5. 安全规则不变：权限模式、审批、本地策略都照旧，`chat` Run 占用工位。

0022 第 1 条“只和主管对话”改为“默认和主管对话”，其余内容不变。

## Alternatives

- **所有话都经过主管转达**：0022 的做法。慢，会走样，还要多花一次调用。
- **私聊也叫醒主管**：每句话都要多一次调用，主管还容易插手用户和 agent 之间的事。
- **私聊原文进主管的历史**：会撑大上下文，而且大多数私聊内容和主管的判断无关。只放提示加按需查看就够了。
- **接不上会话就开新会话**：新会话没有上下文，已经不是在“和那个 agent 对话”，用户会误以为它还记得。

## Consequences

- 主管有时会对私聊里已经说过的事一无所知，需要靠本轮环境里的提示去查看。真实模型验收时要观察它会不会重复 agent 已经做过的事。
- 新增 Run 用途 `chat` 和消息种类 `dm`；任务的状态会因为私聊在“已结束”和“进行中”之间来回变化。
- 设计见 `work/specs/notes-meetings-agent-chat`。
