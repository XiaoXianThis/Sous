# 0023 AI 代理用户决定大多数事项

- Status: Accepted
- Date: 2026-11-06

## Context

用户的原则是“95% 不找我”，只亲自决定关键中的关键。常规可恢复的工作由 AI 自主处理，避免审批和验收反复打断。

## Decision

- 未设置权限模式时使用 auto，任务、git、部署检查、项目创建及直接创建 Run 和设置接口保持一致；显式设置的模式优先。
- 审批员是用户的代理人：任务范围内可恢复的必要操作批准；不合适的操作拒绝并给 agent 替代办法，只有底线、不可恢复或任务外影响交用户。
- allow 仍要求 high；deny 的 high 和 medium 都生效，low 交用户。
- 每个 Run 的 AI 批准上限为 150，同一操作的 AI 拒绝上限为 3。
- 审查岗位失败或没有明确结论时，优先使用可用的验收模型检查工作 Run；没有模型、工作 Run 缺失或模型失败才等用户验收。模型调用不持有引擎锁，应用结果前重新检查任务和最新 Run。
- 主管先根据对话、记忆、git_status 做合理判断并说明假设；分支不确定时用当前检出分支。验收默认由 AI 判断，不通过先返工；失败先自行解决最多两轮。受保护分支、强制推送、删除远端分支、detached HEAD、他人分支仍先问。任务做完不自动提交推送。
- Node 的硬信号、底线和 aiNever 不变；RoleServer 规则不变。

## Alternatives

- 保持人工模式作为兜底：会持续打断用户，不符合代理决策的目标。
- 放宽 Node 硬信号或服务器规则：会越过用户保留的关键决策边界，因此不采用。

## Consequences

常规工作和验收更多由 AI 完成，拒绝会带着替代建议回到 agent。只有关键风险、低把握或超出上限时才打扰用户。用户之前在设置里手动选过 default 时，新的默认值不生效，需要去设置里改成自动。
