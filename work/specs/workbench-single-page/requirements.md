# 工作台单页：需求

## 背景

M5 的工作台是“项目 × 机器”的二维矩阵，外加总览、项目、待处理三个分开的页面。它把机器当成了第二维：同一个项目在每台机器上重复一次；正在干活的子 agent 只画成一个头像；任务、审批、进度分散在不同页面。

core 里的使用模型已经是一维的：主管（主 agent）不直接操作电脑，只管理项目、创建任务、按岗位派发子 agent、收集进度和通知（`apps/core/internal/prompts/prompts.go:24`、`apps/core/internal/task/tools.go:18-19`）。界面应该让这条链路成为第一眼能看懂的东西。

## 目标

1. **工作台是一页**：项目卡片是唯一的单位；机器、部署目标和远端降级成卡片里的“位置”。
2. **任务和子 agent 是同一件事**：一个任务同一时刻最多一个活跃 Run；运行中的任务直接展开成 agent 卡，标题、状态、模型、机器和 2 行实时输出都在卡片里。
3. **任务只有一种状态**：待办、进行中、要你处理、已结束，作为任务行上的一个 badge，不再按状态分栏。
4. **总览、项目、待处理合并进工作台**：项目集合就是卡片网格，待处理是筛选，项目页和任务页变成 sheet。
5. **不改 core 的执行逻辑**：主管的提示和工具、任务引擎、策略、路由都不动；本 spec 只改 `apps/web`，以及一个可选的 `/overview` 字段。

## 名词

| 名词 | 在本 spec 里的意思 |
|---|---|
| 项目 | 一个 git 仓库，身份是规范化后的远端地址；内置“杂项”项目收容不属于仓库的任务 |
| 位置 | 项目实际存在的地方：开发机（Mac / PC / Linux）、部署目标服务器、远端仓库（GitHub / GitLab / …） |
| 任务 | 属于一个项目、分给一个岗位的管理单元；状态只有四种（见 R4） |
| 岗位 | 可配置的“人”：agent、模型和思考强度、岗位说明、默认权限模式 |
| 子 agent | 岗位使用的编程 agent（opencode、Kiro、Claude 等），一次任务由它在某台机器上执行 |
| Run | 子 agent 的一次执行会话：一个岗位在某台机器上做一次任务 |
| 主管 | 和用户对话的主 agent（代码里的 supervisor），只做项目管理、派活、盯盘和通知 |

## 核心模型

```
项目
├── 位置：Mac / PC / 服务器 / GitHub（可以有多个）
└── 任务（可以有多个）
    ├── 状态：待办 / 进行中 / 要你处理 / 已结束
    └── 执行：岗位 → 子 agent → 在机器上的一次 Run → 思考 / 工具 / 文本
```

- 机器不是第二维：它是项目的属性，也是任务执行时的一个字段。
- 一个任务同时最多一个活跃 Run；多个 Run 是同一条任务的不同阶段（工作、rebase、交付）。

## 范围

| 本 spec | 不做 |
|---|---|
| 单页工作台、项目卡片、瀑布流 | 拖拽排序、自由画布、卡片内嵌可编辑表单 |
| 四种任务状态和统一的状态视觉 | 改任务引擎的状态机、验收和交付流程 |
| 子 agent 卡片、2 行实时输出、Run 详情弹窗 | 改 ACP、agent 适配器、思考内容的归档 |
| 位置行（机器、部署、远端） | 新增机器类型；Mac / PC / 服务器沿用 `node.os` 和 `node.role` |
| 总览 / 项目 / 待处理合并 | 改聊天边栏的交互和推送通道 |
| 深链接和推送链接兼容 | 新的通知渠道 |

## 需求

### R1 单页工作台

1. 工作台是唯一的业务页面。桌面：左边图标栏（工作台、对话、设置）+ 工作台主体 + 可收起的聊天边栏。手机：底部三个标签（工作台、对话、设置）。
2. “总览”“项目”“待处理”不再是独立页面：
   - 项目集合就是工作台的卡片网格；
   - 待处理是工作台顶部的一个筛选和角标；
   - 项目详情和任务详情变成 sheet（R7）。
3. 设置仍然是全屏弹窗，不进入工作台路由。
4. 聊天边栏保持现状：对话、历史下拉、上下文标签、Run 一行显示。

### R2 项目卡片

1. 每个项目一张卡片，“杂项”也在其中（排在最后）。
2. 卡片用**瀑布流**排列，允许高度不齐；列数随窗口宽度变化，手机上是一列。
3. 卡片从上到下包含：
   - 项目名（点击打开项目 sheet）、最需要注意的状态、任务计数；
   - 位置行（R3）；
   - “正在工作”区（R5）：每个运行中、暂停或等你审批的 Run 一张 agent 卡；
   - 任务列表（R4）：标题 + 一行摘要 + 状态，运行中的任务不重复出现；
   - 需要你处理的事项：审批卡、失败或受阻任务的重试；
   - 底部：待办计数、PR 待合并数，以及“新建任务”“部署”“打开项目”。
4. 一张卡最多显示 4 条任务和 2 个 agent 卡；“还有 N 个”打开项目 sheet，不把卡片撑长。
5. 卡片排序：需要你处理 > 进行中 > 只有待办 > 空闲；“杂项”最后。同组按项目名排序。
6. 卡片有稳定 key（项目 id），刷新数据时不能整块重建或闪烁。

### R3 位置

1. 位置行显示项目实际在哪些地方：
   - 开发机：按 `node.os` 显示 Mac / Windows / Linux，按 `node.role` 显示服务器；
   - 部署目标：服务器 + 目录；
   - 远端：`projects.repo_url` 的 host（GitHub / GitLab / 其他），可点击；
   - 没有任何机器位置时显示“只在 <host>”或“不在任何机器上”。
2. 机器离线时 chip 变灰，但仍然显示；部署目标用虚线边框区分。
3. 点位置 chip 打开“设置 → 机器”；点远端 chip 在新窗口打开仓库地址。
4. 同一个项目在几台机器上就显示几个 chip，不复制卡片。

### R4 任务

1. 任务属于项目，由岗位的子 agent 执行；卡片里一个任务占一行。
2. 任务行内容：
   - 状态 badge：四种状态之一；
   - 标题：一行，超出省略；
   - 摘要：一行，岗位 · agent · 机器 · 当前阶段或 `status_reason` 的截断；
   - 进行中的任务带一个紧凑阶段条（复用 `StageBar`）。
3. 状态只有四种：

   | 状态 | 含义 | 包含的详细状态 |
   |---|---|---|
   | 待办 | 还没开始，或还没派发 | 收件箱、待规划、待开始 |
   | 进行中 | 子 agent 正在做，或 sous 正在自动验收 | 排队、执行中、验收中 |
   | 要你处理 | 需要用户做决定或动手 | 等你审批、已暂停、受阻、失败、等待机器、PR 待合并 |
   | 已结束 | 已经完成或取消，不再需要动作 | 完成、已取消 |

   详细状态（排队、验收中、已暂停、失败、PR 待合并等）只作为 badge 上的补充文字，不改变四态。
4. 任务不按状态分栏。卡片里按“要你处理 > 进行中 > 待办 > 已结束”排列，同组按更新时间倒序。
5. 任务行只显示标题和一行摘要；完整阶段、每个 Run 的步骤、diff、审批记录和操作都在任务 sheet 里。
6. 点击任务行打开任务 sheet；任务 sheet 里的操作和现在任务页一致（暂停、继续、追加指令、取消、重试、打开 PR、日志、改动）。
7. 卡片上的“要你处理”可以就地处理：审批、重试、取消，不需要回到聊天。

### R5 子 agent

1. 运行中（含暂停、等审批）的 Run 在卡片里显示为 agent 卡：
   - 第一行：任务标题和状态；
   - 第二行：岗位 · agent 名（opencode、Kiro 等）· 模型 · 思考强度 · 机器；
   - 下面 2 行活动流：思考、工具调用、文本的最新内容，实时更新；
   - 有审批时在卡里显示审批卡。
2. 排队中的 Run 不显示 agent 卡，作为任务行的“排队”状态。
3. 点击 agent 卡打开 Run 详情弹窗：完整活动流、工具步骤、计划、审批、暂停 / 继续 / 取消、日志和改动。
4. 模型和思考强度优先取 `run.options`（`model`、`thought_level`），其次机器的 `agents[].defaults`，再其次 agent 报告的当前值；都拿不到时显示“默认”。
5. agent 不支持某个选项时不要报错，省略那一项。
6. 2 行活动流在页面打开期间实时更新；刷新页面后允许先显示“等待输出…”，不要求补历史（见 design 7.3）。

### R6 主管的职责（不变）

1. 主管仍然不能直接操作电脑：只能管理项目、创建 / 更新 / 派发任务、给正在跑的 Run 追加消息、取消、盯盘和通知。
2. 本 spec 不改 supervisor 提示、任务引擎、策略和路由；只把已有的链路显示出来。
3. 界面上不出现“主管直接执行”的入口；主 agent 的入口只有聊天。

### R7 路由、深链接和推送

1. `#/` 打开工作台。
2. `#/task=<id>` 打开工作台并在上面弹任务 sheet。
3. `#/project=<id>` 打开工作台并在上面弹项目 sheet。
4. `#/inbox` 打开工作台并切到“要你处理”筛选。
5. `#/projects` 兼容旧链接，等同 `#/`。
6. `#thread=<id>` 仍然是聊天；旧的推送链接（`#approvals`、`#task=`）继续可用。
7. 打开 sheet 记入浏览器历史；返回键 / 浏览器后退关闭 sheet。
8. 推送的 Service Worker 逻辑不变。

### R8 手机与可访问性

1. 手机上工作台是一列瀑布流；agent 卡的 2 行截断不变；三个底部标签：工作台、对话、设置。
2. 可点区域有可读的 `aria-label`；项目名、任务行、agent 卡是并列的按钮，不能互相嵌套。
3. Esc 关闭最上层 sheet，焦点回到打开它的元素。
4. 浅色和深色都可读；颜色只用 `app.css` 的变量；状态图标和颜色复用 `status.ts`，不在组件里另定义。

### R9 数据与实时性

1. 项目、机器、任务、Run、审批来自 `GET /overview`；待处理数量和完整的待处理任务沿用 `GET /inbox`。
2. 工作台维护一份实时活动缓存（按 Run id），接收 `run.output` 和 `run.update`；`run.started`、`run.ended`、`run.paused`、`run.resumed` 触发一次去抖动的 `/overview` 重拉。
3. 流式输出本身不触发 `/overview` 重拉，也不触发卡片重排。
4. 事件流重连后从已存事件继续；`run.output` 不重放，允许丢失重连期间的活动。

## 验收场景

1. **项目卡片**：两个项目、三台机器（Mac 开发机、Windows 开发机、Linux 服务器）、一个 GitHub 远端。工作台只有项目卡片，没有二维表格；每张卡的位置行正确，同一个项目在两台机器上只有一个 chip 组、不复制卡片。
2. **本地图**：一个项目在两台开发机上都有仓库，卡片里出现两个机器 chip；其中一台离线时 chip 变灰。
3. **子 agent**：派一个任务给前端岗。卡片出现 agent 卡，显示岗位、agent、模型、思考强度、机器和两行实时输出；输出持续更新，工作台不整体重绘、不重新拉 `/overview`。
4. **审批**：agent 要求 push。审批卡出现在 agent 卡里；点批准后继续执行，状态回到进行中；点拒绝后任务进入要你处理。
5. **四态**：待办、排队、执行中、验收中、等你审批、失败、PR 待合并、完成分别落在四种状态里，文字和图标正确。
6. **任务行**：卡片里只显示标题和一行摘要；点开 sheet 才能看到阶段、Run 步骤、diff 和操作。
7. **瀑布流**：三张高度不同的卡片排列后没有明显空洞；窗口变窄时列数减少，手机上是一列；卡片顺序没有跳变。
8. **手机**：一列、三个标签、sheet 全屏；深色模式正常；中文输入法不影响聊天。
9. **深链接**：推送 `#task=<id>` 打开工作台并弹出任务 sheet；浏览器返回关闭 sheet；`#/inbox` 只显示需要处理的卡片。
10. **零后端**：不改 core 的情况下，除“刷新后没有历史输出”外，以上场景全部可用。
