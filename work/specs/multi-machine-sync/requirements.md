# 多机项目：版本、同步、合并、进度

一个项目常常同时在几台机器上有 checkout（笔记本、台式机、服务器）。sous 要让它们不互相踩，也不让用户去记“哪台机器上是最新的”。

## 现状

- 项目身份是远端地址（`project.Key`），每台机器上的 checkout 是项目的一个位置（`project_nodes`），扫描自动登记。
- 代码任务在 worktree 里干活，以 PR 交付（0009），PR 有冲突时派 rebase Run；合并后自动部署。任务和 Run 的进度都在 Hub 上，所有设备看到的一样。
- 问题：
  1. worktree 从这台机器 checkout 的**本地 HEAD** 开分支，不先 fetch。机器落后于远端时，新任务基于旧代码，后面必然冲突。
  2. 看不到每个位置的状态：在哪个分支、落后远端多少、有没有没提交的改动。用户在某台机器上手动改了东西（终端、文件编辑），别的机器和 sous 都不知道。
  3. 两台机器上的任务可能同时改同一块代码，只有到 PR 冲突时才发现。

## 需求

- R1 新任务总是基于远端的最新代码开始，不管这台机器的 checkout 停在哪里，也不动它的工作区。
- R2 页面上每个位置显示：分支、相对远端的领先 / 落后、未提交的改动数、上次 fetch 的时间。主管的环境说明里也有。
- R3 一键同步一个位置：fetch，然后在工作区干净、可以快进时快进；不能快进或有改动时只报告，不自动合并、不丢改动。
- R4 位置上有未提交或未推送的改动时，可以一键存成远端的 WIP 分支（`sous/wip/<机器>-<时间>`），让别的机器和任务能接着用；绝不推到主分支。
- R5 同一项目里同时进行的代码任务，改动的文件有重叠时提醒主管（按已产生的 diff 判断），由主管决定排队（`depends_on`）还是继续。
- R6 不做 git 之外的文件同步：`.env`、本地数据等按机器各自维护；sous 不复制仓库以外的文件。
