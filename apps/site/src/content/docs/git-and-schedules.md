## 1. Git 操作：提交、合并、推送、PR 与撤销

**为什么由 Node 执行受控 Git 操作**：所有交付类的 Git 操作都作为 `purpose: git` 的专用 Run 在持有该任务分支或快照的机器上执行。Node 使用 `internal/workspace` 中写死的安全命令（绝不拼接任意 Shell、绝不加 `--force`），且每一步写入同样经过本地策略校验。

你只需在对话里对主管说出意图，主管会先调用 `git_status` 查看当前分支与远端状态，再调用对应的工具：

| 操作意图 | 主管工具 / `git.op` | 适用于 | 具体执行行为与安全保护 |
|---|---|---|---|
| **提交改动** | `git_commit` (`commit`) | `worktree` / `in_place` | **Worktree 任务**：在任务 worktree 中执行 `git add -A` 并提交（可选 `squash: true` 将基线提交之后的多次提交压成一个）。<br/>**就地任务（`in_place`）**：利用影子仓库的开始快照与结束快照，**只提交本次任务改过或新建的文件**（通过临时索引生成提交并移动分支），你自己在工作区里修改的其他文件或暂存区完全不受影响。 |
| **合并到本地分支** | `git_merge` (`merge`) | `worktree` | 先检查目标分支（如 `main`）为本地分支且其工作区干净（无未提交改动）；将 worktree 中剩余改动提交后执行 `git rebase <目标分支>`。**若发生冲突，立即 `rebase --abort` 并原样返回冲突文件列表，什么都不改**；若无冲突，则对目标分支执行 **`git merge --ff-only`（仅快进合并）**，随后清理该任务的 worktree 与临时分支（保留合并前分支提交 `task_tip` 供撤回使用），任务 `git_state` 变为 `merged`。 |
| **推送到远端** | `git_push` (`push`) | 本地分支 | 执行 `git push <remote> <branch>`，**永远不会加 `--force` 或 `--force-with-lease`**。推送成功后自动触发一次仓库扫描。 |
| **创建 Pull Request** | `git_pr` (`pr`) | `worktree` | 提交 worktree 中剩余改动，执行 `git push -u origin <任务分支>`（在 `auto` 模式下推送非受保护分支属常规操作，直接放行），然后调用 `gh pr create --head <任务分支> --base <目标分支>` 创建 PR，返回 PR 链接并清理 worktree，任务 `git_state` 变为 `pr`。 |
| **撤回提交或合并** | `git_undo` (`undo`) | 已提交 / 已合并分支 | 根据本机 `~/.sous/gitops.jsonl` 记录，撤回 `sous` 在该分支上最近一次尚未撤回的 `commit` 或 `merge`：**如果该提交已经推送到任何远端分支，或者分支在那之后又被移动过，则拒绝撤回**；否则将目标分支回退到合并/提交前的位置，并把被合并删掉的任务分支恢复到 `task_tip`。 |
| **丢弃任务分支** | `git_discard` (`discard`) | `worktree` | 删除该任务的 worktree 与任务分支（`git branch -D`，属于 `irreversible` 类别，需用户批准），任务 `git_state` 变为 `discarded`。 |
| **撤销就地任务改动** | `task_restore` (`restore`) | `in_place` | 对比影子仓库记录的开始快照（`refs/sous/<id>`）与结束快照（`refs/sous/<id>-end`），**只恢复本次任务改过的文件、删除本次任务新建的文件**。你自己在工作区新建或修改的文件，以及任务结束后又被修改过的文件**一律不动**（并在结果中列出），任务 `git_state` 变为 `restored`。 |

## 2. 多机仓库同步与存成 WIP 分支

**什么时候用**：你的同一个项目同时克隆在笔记本和台式机上。你在台式机上推了新提交，或者笔记本工作区里有一半没写完的改动想先保存起来再切电脑。

在工作台每个项目卡片顶部，每台电脑的位置标签旁都会显示当前的 Git 状态标记（由 daemon 每 10 分钟后台 `git fetch` 与扫描更新）：

- **`↓N`（落后上游 N 个提交）**
- **`↑N`（有 N 个本地提交尚未推送）**
- **`●`（工作区有未提交的修改或未跟踪文件）**

点击该位置标签，会弹出当前分支详情与两个快捷操作按钮：

1. **同步（Sync，`POST /api/v1/projects/{id}/locations/{node}/sync`）**：
   - 先执行 `git fetch`，如果当前分支可以快进（Fast-forward），则快进到上游最新提交。
   - 如果工作区有未提交改动（`dirty`）、与上游已分叉（`diverged`）或没有设置上游分支（`no_upstream`），Node **什么都不会改**，并明確返回原因，绝不会冲掉你的本地代码。
2. **存成 WIP 分支（Save WIP，`POST /api/v1/projects/{id}/locations/{node}/wip`）**：
   - 把那台机器当前工作区里所有未提交的改动（含未跟踪的新文件，遵守 `.gitignore`）以及尚未推送的提交，通过**临时 Git 索引**打包成一个提交，直接推送到远端 `origin` 的 **`sous/wip/<机器名>-<时间戳>`** 分支。
   - **你本机当前的文件、暂存区和所在分支保持原样不变**。这样你既备份了半成品，又能在另一台电脑上随时检出 `sous/wip/...` 接着改。

## 3. 定时任务（Schedules）与自动跟进

### 配置 Cron 定时任务

**什么时候用**：你想让主管每天早上汇总各个项目的进展、定时让服务器跑一次健康巡检、或者每周五整理一次本周完成的任务。

你可以在网页 **设置 → 定时任务** 中添加，也可以直接在对话里对主管说「帮我建个定时任务，每天早上 9 点检查一下生产服务器磁盘和容器状态」：

- **标题（`title`）**：定时任务名称，如 `每日早报与服务器检查`。
- **Cron 表达式（`cron`）**：标准 5 段格式 `分 时 日 月 周`（如 `0 9 * * *` 表示每天 09:00，`*/30 * * * *` 表示每 30 分钟），也支持 `@hourly`、`@daily`、`@weekly`。
- **时区（`tz`）**：IANA 时区名称（如 `Asia/Shanghai`；留空则使用免打扰设置里记录的设备时区，再缺省使用 Hub 所在服务器时区）。
- **提示词（`prompt`）**：到点时发给主管的指令正文。
- **目标对话（`thread_id`）**：留空则默认发到主线对话。

到点触发时，Hub 会在目标线程写入一条 `kind: trigger`（以 `【定时任务：标题】` 开头）的消息叫醒主管；主管可以调用只读工具、创建任务或向你发推送通知。在设置页点击某条定时任务旁的 **立即运行**（`POST /api/v1/schedules/{id}/run`）可随时手动触发一次测试，不影响下一次计划时间。

### 自动跟进（Follow-ups）与巡检（Inspector）

除了你设置的定时任务，Hub 还内置了两个后台守护循环（参数可在 `hub.yaml` 的 `triggers` 与 `inspector` 中调整）：

1. **自动跟进扫描（默认每 5 分钟检查一次）**：
   - 受阻或失败且用户尚未点「已知晓」的任务超过 **4 小时**（`blocked_after: 4h`）；
   - 仍在运行中的 Run 超过 **2 小时**（`run_timeout: 2h`）；
   - 待人工审批超过 **2 小时**（`approval_after: 2h`）；
   - 主管向用户提问未获回复超过 **8 小时**（`question_after: 8h`）。
   每个条件对同一对象只会触发一次跟进提醒，绝不反复轰炸。
2. **巡检 Agent（默认每 10 分钟检查一次）**：
   - 取代生硬的「花费预算熔断」（决策 `0006`）。当某个 Run 连续重复调用相同工具达到 **5 次**（`repeat: 5`）、卡住无输出超过 **30 分钟**（`stalled_after: 30m`）、运行超过 **3 小时**（`long_after: 3h`）或单周期消耗超过 **200 万 Token**（`token_alarm: 2000000`）时，巡检 Agent 会介入检查，按严重程度执行提醒（`notify`）、暂停 Run（`pause`）或停止 Run（`stop`）。
   - 此外，Node 本地只要发现子 Agent 对同一个工具连续调用失败 **4 次**，就会立即上报 `stuck` 事件，由 Hub 自动暂停该 Run 并在主线提醒你。
