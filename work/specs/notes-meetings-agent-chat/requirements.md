# 记事本、会议和直接与子 agent 对话

## 现状

- 用户只和主管对话（0022）。想直接问某个子 agent 一句，只能在任务页发追加指令（`/runs/{id}/message`），而且只对正在运行的 Run 有效；任务结束后接不上它的会话。
- 想法随时会冒出来，但还不到交给主管的时候。现在只能先发进对话（主管会立刻处理），或者记在别处。
- 需求不确定时要反复讨论。讨论很长，全部进入主线或项目对话的上下文，挤占窗口、触发整理，还会把讨论中途被否掉的想法带进摘要和记忆。

## 需求

### 记事本

- N1 随手记：桌面左侧图标栏有“记事本”抽屉（也可以用快捷键打开），手机上从底栏进入。一条笔记就是一段文字，可以带附件，可以挂到某个项目上。没有标题和标签这类必填项。
- N2 手动抛出：选一条或多条笔记，点“发给…”，目标可以是：主线、某个项目对话（可选具体话题）、某个子 agent（D 节）、开一个会（M 节）。发送前可以编辑合并后的文字。发出去是一条普通的用户消息，界面上标“来自笔记”。
- N3 状态：笔记分为未发送、已发送、已归档。已发送的笔记记下去了哪里（线程、话题、消息），点击可以跳过去；同一条笔记可以多次发送。
- N4 主管看不到记事本：没有读笔记的工具，环境说明里也不提。只有用户发出的内容才进入对话。
- N5 跨设备：`sous note "..."` 在已配对的机器上记一条笔记（设备令牌）。手机系统分享入口在 PWA 支持时再做。

### 直接和子 agent 对话

- D1 对象切换：项目对话的输入框有“对象”切换，默认是 sous，可以选这个项目里的 agent：正在运行的工作 Run、已结束但留有会话的任务、项目顾问。也可以在任务的 Run 行上点“私聊”。当前对象一直显示在输入框上，对象不是 sous 时输入框边框换成强调色。
- D2 投递：Run 正在运行时作为追加指令发出；任务没有在跑的 Run 时，接着原会话开一个 `chat` Run（同一台机器、同一个 agent、任务原来的权限模式），每句话一个；顾问直接进它的只读会话。私聊不带附件。
- D3 显示：私聊（用户的话和 agent 的回复）挂在对应 Run 或任务那一行下面，作为可折叠的块显示，样式和顾问回答一样，标着“agent · 私聊 · 任务”。
- D4 已结束的任务：用户私聊一个已结束任务的 agent 时，任务回到“进行中”。这个 `chat` Run 结束时，任务引擎照常发汇报：有新改动就说明改了什么，没有改动就静默回到原来的状态。
- D5 主管知情：私聊不叫醒主管。私聊内容记进任务的沟通记录（`from: user, to: agent`）。主管的本轮环境里列出“用户直接和任务 X 的 agent 聊过 N 条，最近一次在 …”，主管需要时用 `task_result` 或 `thread_read` 查看。私聊产生改动时，汇报会叫醒主管（0025）。
- D6 安全：审批、权限模式、本地策略都不变；`chat` Run 占用机器的工位，和返工一样。

### 会议模式

- M1 会议是独立的对话：它有自己的上下文、分段和摘要，聊多长都不影响主线或项目对话。可以限定在某个项目里。
- M2 开会：在主线或项目对话里，从某个话题或笔记点“开会”；主管觉得需求不明确时也可以用 `meeting_propose` 提议开会，由用户确认后开始。会议只带一份简报：父话题的当前结论、相关的摘要条目、用户的开场问题，不带整条对话。
- M3 主持人：默认是 sous，使用会议专用提示（多问、给出选项、记下分歧）。开会时可以换主持人用的模型和思考强度。会上只开放只读工具（`project_read`、`consult`、`web_search`、`web_fetch`、`memory_search`、`thread_search`、`thread_read`），不建任务、不做 git 操作。
- M4 请人参会：主持人可以用 `consult` 请项目顾问发言；用户可以在会议输入框里把对象切换成某个任务的 agent（复用 D2 的投递）。发言都作为会议消息显示。
- M5 散会：用户点“散会”或在会上说结束。`compactor` 按固定栏目生成会议纪要：议题、结论和决定、被否掉的方案和理由、未决问题、行动项。每条带 `[#seq]`，指向会议原文。“结论和决定”和“行动项”经过和 0020 一样的程序校验，不会遗漏。
- M6 确认后发出：纪要先给用户看，可以修改，确认后才发到父话题，以“会议纪要”卡片显示，带“查看原始记录”链接。设置里可以打开“纪要直接发出”，打开后不再确认（记成用户习惯）。
- M7 主管接手：纪要发出时叫醒主管。由主管决定怎么处理行动项：建任务、向用户确认，或者记下来。
- M8 回查：主管读到纪要里的 `[#12]` 时，用 `thread_read {thread, seq}` 展开会议原文；`thread_search` 可以限定在某次会议里。主管只能读当前对话关联过的会议。
- M9 续会：已经结束的会议可以重新打开，在同一个会议里接着讨论；再次散会时生成修订版纪要，作为新的一条发到父话题，旧版本在界面上折叠成“已被第 N 版取代”。
- M10 记忆：会议进行中的整理只写摘要、不写长期记忆。纪要发到父对话后，跟着父对话的整理流程处理记忆。
- M11 列表：设置旁边或主线里能找到所有会议（进行中、已结束），按时间排列，可以搜索。

## 不做

- 主管读取记事本。
- 会议里执行有副作用的操作。
- 多人同时参会（目前只有单用户）。
