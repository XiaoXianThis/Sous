# 0024 预设、每台电脑的 agent，以及更顺手的主管

- Status: Accepted
- Date: 2026-11-07

## Context

用了一阵后，用户提了这些问题：

- 主管一轮最多调 12 次模型（`MaxSteps`），稍复杂的查询就被截断。
- 子 agent 不能按任务挑模型，只能靠岗位带的会话选项。
- “岗位”（0013）的意义不明确：后端、前端、运维这些角色说明对结果帮助不大，用户真正想挑的是“agent + 模型”的组合，比如 codex + gpt-6.1-terra 求快、claude code + opus 5.5 当主力、opencode + deepseek 便宜但慢。而每台电脑装的 agent 不一样。
- 自动审批还是常常找用户。看库里的记录，大部分是审批 agent 在信息不够时选了 ask_user：看不到脚本内容、不确定进程是谁的、临时目录里的脚本、agent 自带的联网搜索。
- 主管看不到电脑上的情况，问一句“服务起来没有”也要派任务。
- 验收是 `task_create` 的必填项，只想调查一件事也要选验收方式。
- 默认 agent 不能按电脑设置，agent 不能在某台电脑上停用，也不能加自定义的 agent。

## Decision

1. **主管一轮最多 50 次模型调用。** 倒数第二步的工具结果后面附一句“不要再调工具，说明做到哪了”，最后一步用来汇报，用户说“继续”就接着做。同一轮里完全相同的工具调用（名字和参数都一样）最多执行 2 次，之后直接返回提示，不再执行。
2. **任务可以带自己的模型和思考强度。** `task_create` / `task_update` 多了 `model`、`effort`（`consult` 也有，只在开新会话时生效），存在任务的 `options`，派发时盖在预设的选项上。Hub 只写 `model` / `effort` 这两个通用键，Node 按选项的 category（`model`、`thought_level`）找到 agent 自己的选项 id，值可以按名字写，不分大小写。主管的环境说明按电脑列出每个 agent 能选的模型和思考强度。
3. **岗位改成预设。** 预设是“agent + 模型（+ 思考强度、权限模式）+ 定位”。定位只给主管看，用来挑选，不再拼进 agent 的提示词。环境说明里写出每个预设能在哪些电脑上用（装了、没停用、没退出登录），没有电脑能用时主管换一个，或者直接指定 agent。新装只内置一个“验收”预设（`review: agent` 用）；已有的岗位保留成预设，用户自己改、删。数据表和接口仍叫 `personas`。
4. **自动审批：信息不够时拒绝，不上交。** 审批 agent 的提示词改成：看不到脚本、不确定进程是谁的、不确定文件是不是任务产生的，都 deny，并告诉 agent 先怎么确认；访问本机服务做检查、结束任务自己启动的进程、在 worktree 或就地任务目录里删除 git 能恢复的文件、agent 在系统临时目录里的草稿脚本、agent 自带的只读工具（联网搜索等），在任务需要时批准。审批卡片附上的脚本内容扩展到解释器运行的脚本（`node x.mjs`、`python3 x.py` 等）和系统临时目录里的脚本。硬信号、底线、`aiNever` 和各种上限不变。
5. **主管能看一眼电脑：`machine_look`。** 在一台电脑上执行一条命令，由那台电脑按只读档位（`policy.ModeReadOnly`，Hub 不能放宽）判断，另外拒绝打印环境变量和读 `.env`；20 秒超时，输出最多 16 KB。每轮最多 4 次。它只用来判断和回答，改东西、跑构建测试、多步排查和调研仍然建任务。需要电脑开着远程管理（`remote_admin`）。
6. **验收不是必经的一步。** `review` 不填就是 `none`；要验收时 `on_fail` 不填就是返工。提示词要求调研、提问、小改动不验收，只在改动大、风险高或用户要求时验收。用户只想知道一件事时，主管先用 `project_read`、`machine_look`、`consult` 查清楚直接回答。
7. **每台电脑的 agent 在 node.json 里配置。** `default_agent`（这台电脑的默认 agent）、`disabled_agents`（停用，不会被选上，指名也不行）、`custom_agents`（`[{name, title?, command}]`，任意 ACP agent）。选 agent 的顺序：任务指定 > 预设 > 项目默认 > 这台电脑的默认 > 全局默认 > 任何能用的。`custom_agents` 决定这台电脑会运行什么，所以从 Hub 远程编辑 node.json 时保持磁盘上的值，只能在本机改（和 0012 一样，请求里不带命令）。

0013 的“岗位”被第 3 条取代；0023 里“验收默认由 AI 判断”被第 6 条取代。

## Alternatives

- **预设绑定电脑**（每台电脑各配一套）：更精确，但用户要维护很多份；现在预设和电脑无关，由主管按可用性挑。
- **预设带备选（主力用不了时自动换）**：自动但不透明；现在把可用性写进环境说明，由主管换并在派发时说明。
- **主管直接执行任意命令**：最方便，但主管会去干编程 agent 的活，用户也说主管不该直接上手；只读加每轮上限是折中。
- **审批 agent 能读文件（工具循环）**：更聪明但更慢、更贵；先把脚本内容附在请求里，信息不够时让 agent 自己去确认。

## Consequences

- 主管的环境说明更长（每台电脑的模型列表、每个预设的可用电脑），每轮都会带上。
- `machine_look` 的结果进入主管的上下文：只读档位挡住了改动，但 `ps`、日志里仍可能有敏感信息；它和 `project_read` 一样受远程管理开关控制。
- node.json 的 `agents`（覆盖内置 agent 的启动命令）仍然可以远程编辑，这是 0012 以前就有的行为，没有在这里收紧。
- 数据库多了 `tasks.options`（迁移）；`AgentInfo` 多了 `disabled`、`default`、`custom`。
