# Sous Supervisor Benchmark

## 评测目标

1. **主管能力**：同一模型、同一合成任务和预算下，多少任务严格达到用户目标？不把模型裁判、措辞、额外工具调用、成本或时延掺进 100 分主分。
2. **编排差**：真实 Sous 与最小参考编排的配对通过率差。参考只通过公开 API 使用真实任务/派发/记忆后端，不调用 Sous 主管来决策；它不是模型能力上限。
3. **升级差**：固定模型和题库，交错跑 `v0.2.4` 与候选版本，报告净百分点、通过/失败的双向翻转、保守区间、各题失败证据和效率。`v0.3.0` 系列不作为基线。

## 一键运行

在本目录使用 Bun。需要 Bun、Git、tar、Go（`v0.2.4` 使用 Go 1.26），无第三方 Bun 依赖。不需要预启动 app；需要允许本机回环监听。首建需要 Go 依赖缓存或下载权限。`run` 从 Git 对象归档并构建已提交的 `apps/core`，不切换分支、不用宿主现成 `build/core`、不使用未提交修改。Mac ARM64 已验收；其他平台未实测。

```sh
bun run test
bun run bench run --mode offline --version v0.2.4
bun run bench run --mode live --version v0.2.4 --key-file apps/core/.env
bun run bench run --mode live --version v0.2.4 --candidate <candidate-commit> --key-file apps/core/.env
bun run bench show <run-id>
bun run bench compare <older-run-id> <newer-run-id>
bun run bench history
```

- 路径参数 `--key-file` 相对仓库根目录，也可用绝对路径。默认只读 `OPENCODE_API_KEY` 环境变量；`--key-file` 是显式选择，不会自动打开项目或 HOME 私密文件。可以用 `--endpoint <https-chat-completions-url> --model <model-id> --key-env <env-name> --effort <label>` 指定另一个兼容端点；不要把密钥放进命令参数或 URL。基线用配置中的 OpenCode Go 与 `deepseek-v4.1-flash`，供应商只回报其模型标识，不保证背后的不可变快照。
- 正式对照不传 `--case`。`--case <id1,id2>` 只用于复跑；它的题库签名不同。默认最多并行 3 道题、每题每臂 48 个模型请求、每次生成 4,096 token、每批 400 个已发起请求（含预检）。它限制调用数，不保证金额；订阅使用没有可靠的任务级美元账单。`--total-calls` 可另设，改预算会改变可比签名。
- `--candidate` 给出**同一时间窗口**的版本结果，是判断升级的主路径。`compare` 也能用历史记录重算（需要相同签名），但跨会话差值只作描述，不能替代同期 A/B。提交前先固定候选 commit。版本真分包含受测题的产品型失败；未完成、夹具/服务无效不补零、不淘汰失败题。
- 退出码：`0` 批次完成且未触发硬门禁，`1` 硬门禁或离线验收不通过，`2` 缺题、基础设施不全、参数无效或历史对照不可比。真模型普通题错会如实计分，不等于命令失败。无效命令参数没有创建测试批次。

## 测什么、怎样验收

`supervisor-v2` 固定 17 条：只回答、只规划、先澄清、关键约束交接、独立拆分（不人为建立依赖，不测并行加速比）、依赖、指定机器、失败反馈改派、人工验收门、失败事实汇报、长期写入、新会话召回、无记忆负对照、更正、忘记、竞争项目相关性、整理后保持更正。纯规则回复判字段/事实；执行题由真实 Node + ACP fixture worker 在独立临时工作区产出文件，runner 独立比对实际产物、运行结果、调用次数、依赖时序及未经授权的副作用。模型自报 `done` 不是成功证据。人工只审核题库设计和失败归因，不逐题评分。

每臂独立数据库、`SOUS_HOME` 和假工作区。真实模型只接触合成数据、有限工具和其执行回执。模型网关剥离额外工具，只放行共同 tool schema；执行端不接受任意 shell 或路径，应用独立 HOME，只连回环，关闭 web/MCP 和远程控制。这里是**受限的合成场景**，不是给任意 agent 或不可信历史构建的 OS 沙箱。不连接生产数据库、现有 daemon、远程机器或真实仓库。

`offline` 让脚本供应商提供已知正确解，验证同一套独立判题、ACP、审批和造数链；它的 100 分不代表真实模型满分。单元负对照验证“Done 无产物、重复工作、错误机器、依赖抢跑、矛盾答案、范围外工具、缺样本、回包模型漂移”。真实 `live` 不执行离线脚本解；不使用 LLM judge。评分区间是小样本提示，不能解读为线上代表性或通用能力。整理题调用手动压缩且检查覆盖位置，不将保留原文直读误称压缩成绩。

## 自动留档

- **持续更新表**：[历次结果](../../../specs/sous-benchmark/results.md)，从同目录 `results.ndjson` 自动渲染。每个完成归档的批次留一行，包括离线调试、不完整和门禁失败。`supervisor-v1` 是有已知判题缺陷的预跑；其结果保留，不用于正式基线或与 v2 拼接。保留这个索引即可在忽略目录清空后重算后续的历史配对差；详细证据建议额外备份。
- **单次证据**：`work/logs/sous-bench/<run-id>/report.md`、`summary.json`、`attempts.ndjson`。记录实际回复模型、二进制 SHA-256、输入题库及 runner 签名、预算、逐题成功标记、期望/实际、工作副作用、调用状态、所见合成标记和用量覆盖。认证头、密钥以及完整模型请求不会写入档案。`work/tmp/sous-bench-*` 在正常结束/可捕捉中断后清理。`work/cache/sous-bench/` 可重建。
- **效率口径**：成功样本 P50、样本够时的 P95、上游请求 P50、模型调用次数及 input/output/cache token；失败和重试消耗计入单位成功成本的分子，价格不可见不填零。代理缓冲流，因此不把代理或轮询时刻称为产品原生 TTFT。广义产品（PR、真实部署、浏览器、真 worker、并发吞吐和生产成本）不纳入主管主分。
