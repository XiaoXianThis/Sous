# M5 工作台：需求

M4 跑通了“指挥 → 干活 → 审批 → 汇报”的闭环，但实体模型和界面还是以对话为中心：项目要手动登记，子 agent 没有身份，Run 的步骤全部铺在聊天里。M5 把 sous 改成**以项目推进为中心**：sous 管项目、人员（岗位）和任务，并决定在哪台机器上干活；用户只和 sous 对接、做决策，在一个图形化的工作台上看清全局。

用户仍然只有一个人，界面只做中文。

## 核心使用逻辑

```
你 ──对话 / 决策──▶ sous（主管）
                     │ 管理
     ┌───────────────┼────────────────┐
     ▼               ▼                ▼
   项目            岗位(人员)         任务
 (git 仓库,       (agent+模型+       (属于一个项目,
  在哪些机器上)    提示词+权限)       分给一个岗位)
     │                               │
     └──────── 路由：选机器 ─────────┘
                     ▼
         机器（开发机 / 服务器）上的工位
              = 一次 Run（ACP 会话）
```

- **交互单元**：你和 sous 的一条对话（默认就是主线），对话自动带上你在工作台上正在看的东西作为上下文。
- **管理单元**：项目、岗位、任务三个实体。机器是资源，工位是机器上的并发槽位。
- **执行单元**：Run。一个岗位在某台机器的一个工位上做某个任务，就是一个 Run。

## 范围

| M5（本 spec） | 以后 |
|---|---|
| 机器的工作空间和项目自动发现 | 没有 remote 的项目在机器之间同步 |
| 项目成为一等实体，sous 能创建项目、clone 到机器 | 岗位的长期记忆、绩效统计 |
| 岗位档案，sous 按岗位派活 | 自由拖动排布的画布 |
| 机器角色（开发机 / 服务器）和服务器部署、维护 | 操作系统级沙盒（仍是第二期） |
| 工作台界面：总览、项目页、任务页，聊天边栏 | 自动合并 PR（sous 永远不合并） |
| 设置整合进一个全屏弹窗 | 桌面窗口和托盘（apps/desktop） |

## 需求

### R1 工作空间

1. 每台机器可以在 `node.json` 里设置一个或多个工作空间目录（例如 `~/Code`），也可以在设置页远程修改（受 `remote_admin` 约束）。没设置时不扫描，行为和 M4 一样。
2. daemon 扫描工作空间下两层以内的 git 仓库，上报每个仓库的路径、remote 地址、当前分支、是否有未提交改动。启动、工作空间变化时扫描，之后每 10 分钟一次。只扫工作空间，不扫全盘。
3. sous clone 新项目时，放在这台机器的第一个工作空间里。
4. worktree 和一般任务的临时目录仍放在 `~/.sous/` 下，不放进工作空间。

### R2 项目

1. 项目的身份是**规范化后的 git remote 地址**（去掉协议、`.git` 后缀、大小写差异，`git@host:a/b` 和 `https://host/a/b` 视为同一个）。
2. 扫描上报的仓库，remote 已登记为项目的，自动成为这个项目在这台机器上的一个位置；没登记的列为“发现的仓库”，由用户或 sous 一键登记为项目。没有 remote 的仓库只能登记为单机项目。
3. 手动登记项目、手填路径仍然可用（兼容 M4 的数据）。
4. sous 可以创建项目、把项目 clone 到某台机器（经过审批）、修改项目的机器优先级和默认岗位。
5. **新建项目默认使用 [wokspace](https://github.com/XiaoXianThis/wokspace) 规范**：sous 在机器的工作空间里用 `wok init` 创建仓库，再按需要 `wok new <app>` 建 app。创建 GitHub 远端仓库（`gh repo create`）是可选的一步，按 `git-remote` 类审批。用户在对话里明确要别的结构时才不用 wokspace。登记已有的仓库不受影响。
6. 每个任务都属于一个项目；不属于任何仓库的事归到内置的“杂项”项目。
7. 项目可以登记部署目标（见 R4）。
8. 项目记录自己是否是 wokspace（根目录有 `AGENTS.md` 和 `apps/`、`build/`、`docs/`、`work/` 四个目录），供以后的项目面板使用（见 `work/specs/backlog.md`）。

### R3 岗位（人员）

1. 岗位档案包含：名字、头像（字和颜色）、使用的 agent、模型和思考强度（可选，留空用机器上的默认值）、岗位说明（追加到任务提示前的一段提示词）、默认权限模式（可选）、适合的任务类型（代码 / 一般 / 运维）。
2. 内置几个默认岗位（例如后端、前端、审查、运维），用户可以增删改。
3. 岗位和机器无关。同一个岗位可以同时在几台机器上各做一个任务。
4. 岗位不保存跨任务的记忆；长期经验写在项目上（项目说明、仓库里的 AGENTS.md）。
5. sous 派活时选一个岗位；路由选 agent 的顺序变为：任务指定的岗位 > 项目默认岗位 > 全局默认岗位。M4 的 `agent_pref` 作为兼容：没有岗位时按原逻辑。
6. 岗位要的 agent 在机器上没装或没登录时，这台机器不参与路由（和 M4 相同）。

### R4 服务器与部署维护

1. 任意多台 Linux 服务器可以像个人电脑一样配对接入。机器有角色：**开发机**或**服务器**，配对时选择，之后可改。
2. 默认情况下，代码任务只派到开发机，运维任务只派到服务器。
3. 新增第三类任务：**运维任务**。它在项目在这台服务器上登记的目录里就地执行，不建 worktree，不开 PR，以汇报和健康检查结果结束。
4. 项目的部署目标：哪台服务器、哪个目录、部署命令（优先是仓库里的部署脚本）、健康检查命令（可选）。运维 Run 的提示里写明这些，要求 agent 按脚本执行，不要临时发挥。
5. 部署的触发：用户合并 PR 后，在对话里让 sous 部署；或者打开项目的“合并后自动部署”，Hub 定时用 Node 上的 `gh` 检查 sous 开的 PR 是否已合并，合并后由 sous 派一个部署任务。sous 仍然永远不合并。
6. 服务器上的安全默认值：不能使用“完全开放”模式；`irreversible` 和 `delete` 类操作、重启服务一律交给用户审批，不经 AI 审批。这些限制在 Node 本地执行，Hub 不能放宽。
7. 补全 Linux 服务器的接入指南：systemd 用户服务需要 `loginctl enable-linger`，以及在没有浏览器的服务器上登录 agent 的方式。

### R5 工作台界面（桌面）

1. 布局三栏：左边一列图标（总览、项目、待处理、设置），中间是工作台，右边是可收起的聊天边栏。
2. **总览**：行是项目，列是机器（开发机和服务器用不同的图标）。格子里显示正在这里干活的岗位头像和状态图标（执行中、等你审批、排队、暂停、完成、失败），以及部署目标、只有仓库副本等标记。机器离线时整列变灰。点格子或头像进入任务页，点项目名进入项目页。
3. **项目页**：按状态分列的任务看板。每张卡片显示负责岗位的头像、阶段进度条（计划 → 编码 → 验收 → PR → 部署，按任务类型裁剪）和最需要注意的一个状态。顶部显示项目所在的机器和部署目标。
4. **任务页**：阶段时间线、每个 Run 的步骤（计划、工具调用、权限、输出）、diff、审批记录、PR 链接，以及暂停、继续、追加指令、取消、重试。子 agent 的详细步骤只在这里显示。
5. **待处理**：审批、受阻和失败的任务、暂停的 Run、sous 在等你回答的问题。数量显示在图标上。
6. 状态尽量用图标和颜色表示，文字只做补充；同一种状态在所有页面上用同一个图标和颜色。

### R6 聊天边栏

1. 默认只有和 sous 的一条对话（主线）。历史对话收在边栏顶部的下拉菜单里，仍然可以新开。
2. 你发消息时，工作台上正在看的项目或任务会作为上下文一起送给 sous（界面上显示一个可以去掉的标签），让“这个先停一下”之类的话有明确所指。
3. 一个 Run 在对话里只占一行：岗位头像、状态图标、进度。点它，工作台跳到对应的任务页。
4. 需要你当场处理的东西（审批、sous 的提问）仍然以卡片显示在对话里。其他执行细节不进对话。
5. sous 的汇报保持一两句结论，并带上指向任务页的链接。

### R7 设置

1. 左下角只保留一个设置按钮，打开全屏弹窗，左侧分栏：机器、岗位、定时任务、记忆、用量、通知、账号。
2. 机器分栏包含配对、改名、吊销、角色、工作空间、agent 的安装和登录（M4 已有的远程管理）。
3. 退出登录放在账号分栏。

### R8 手机

1. 底部 4 个标签：对话、总览、待处理、设置。打开时默认是对话。
2. 总览在窄屏上变成按项目排列的卡片，每张卡片里是机器图标和岗位头像。
3. 任务页、项目页以全屏抽屉打开。

## 验收场景

1. **自动发现**：一台开发机设置工作空间，里面有 3 个仓库，其中 1 个的 remote 已登记为项目。总览里这个项目自动出现在这台机器的列上，另外 2 个出现在“发现的仓库”里，一键登记后进入总览。
2. **多机同一项目**：同一个仓库在两台开发机上都有。总览里它在两列都有标记；派活按优先级选机器，后续 Run 固定在持有分支的那台机器上。
3. **按岗位派活**：在对话里说“让前端岗把 X 改一下”。任务分给前端岗，总览格子里出现前端岗头像，聊天里只出现一行头像；点进去在任务页看到全部步骤。
4. **clone 到新机器**：让 sous 把项目放到另一台开发机上。审批后 clone 进那台机器的工作空间，总览里出现新的位置。
4a. **新建项目**：让 sous 新建一个项目。它在开发机的工作空间里 `wok init` 出一个 wokspace，`wok check` 通过；用户同意后创建 GitHub 仓库并 push；总览里出现这个项目。
5. **部署闭环**：代码任务开出 PR → 用户合并 → sous 在服务器上派部署任务（自动或手动触发）→ 按部署脚本执行，重启服务时请求用户审批 → 健康检查通过 → 汇报。服务器上无法切到完全开放模式。
6. **界面**：桌面三栏、设置弹窗、手机底部标签都能用；聊天里看不到 Run 的步骤明细。
