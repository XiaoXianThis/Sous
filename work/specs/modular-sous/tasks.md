# Sous 模块化架构：实施与验收任务

> 状态：本机工作区和第一方文本 ACP 主管已可试用。本地沙盒已定为 Microsandbox，Apple Silicon 已有 CLI 执行、审阅与按文件写回，Node 集成与完整发布验收未完成。不以选型、上游声明或 mock 结果标记真实能力完成。
> 本地工作区首轮实测：[验收记录](acceptance.md)。
> 配套：[讨论结果](discussion-results.md) · [新架构图](architecture.md) · [技术设计](design.md)。

## 交付顺序与范围

| 阶段 | 交付 | 退出条件 |
|---|---|---|
| **M0 · 基线** | 固定契约、盘点兼容及权限边界、建立可重复基线 | 可分别验证无主管 Hub、ACP、数据迁移、本机边界和网络分段 |
| **M1 · 模块化与本地 App** | 无主管也可用的 Hub、可换主管、本机工作台 | 一条完整的真 Agent 本地路径；不依赖 Relay，不重建旧任务/记忆 |
| **M2 · 本机沙盒** | 验证并集成 Microsandbox | 从本机授权到复核写回的闭环；边界与恢复验证通过才开放云控本机 |
| **M3 · 标准托管与按需云执行** | 常在线云 Hub、就近云主管、可选云 Node | 所有个人电脑关闭时，手机仍能管理并完成已授权云任务；回收计算不丢成果 |
| **M4 · 混搭与外部接入** | 验证远程主管、远程访问本地 Hub、外部 MCP 与多入口 | 逐组合验证可用性、延迟、授权及故障语义，合格的才列为支持 |

M2 的 Microsandbox PoC可以与 M1 的应用装配交错开展；受控本机执行交付要以 M2 的隔离验收为准。M3 可独立验证云 Node，但**不得在通过 M2 之前开放云 Hub 控制宿主裸 Node**。网络基线从 M0 开始贯穿，不单独拖到上线前。编号用于后续开发拆单，不代表工期或已经批量授权实施 M4。

## M0 · 固定契约并建基线

- [x] **M0-00 归档讨论**：记录原始组合、约束、已选方向、暂缓项、待决项，绘制目标架构和云启停、宿主隔离图。
- [ ] **M0-01 装配与所有权清单**：明确 App/Hub/主管/Node/WebUI 的配置、启动、探活、停止、依赖注入、无组件语义；定下每个工作区唯一 Hub、主管绑定代次、节点身份、消息/事件和 Run ID。发布前让 UI 只要求配置「工作区、主管、执行机器」，不暴露网状拓扑。
- [ ] **M0-02 盘点现有路径**：定位 `hub.Open`、`RunOn`、现有 supervisor HTTP/上下文/模型职责，枚举审批、验收、巡检、摘要等隐式模型耦合；定位 ACP/MCP 桥、事件和 Node 可靠通道、桌面配对兜底与 Relay 依赖。审计本机 `run.go`、`project_files.go`、`daemon.go` 及 shell、Git、管理、更新、文件预览与清理的宿主调用点，给每项标明归属和迁移方式。
- [ ] **M0-03 升级与协议基线**：留代表性的旧 SQLite、历史、任务、记忆、审批和在途 Run 夹具；复用现有信任、配对、Passkey、签名、自主范围与 Relay 加密语义。准备可控 ACP 假 Agent、可复现网络环境和跨组件测试；改动跨应用契约时更新 `docs/api/`，不引入对其他 app 源码的相对依赖。
- [ ] **M0-04 可观测性**：串联 `message_id` / `turn_id` / `run_id` 和实例代次；记录提交→持久化确认、排队、ACP/MCP 次数与 RTT、模型首段正文及送达、完成、节点接收、环境/项目就绪和首进展。p50/p95 按本地/同区/混搭、暖/冷、在线/重连分组；不进日志记录凭据或任务文件正文。

## M1 · Hub 纯工具箱、主管可替换、完整桌面

- [x] **M1-01 Hub 无主管启动**：拆出可选推理运行器，保留业务 API、任务/审批状态机、对话/上下文持久化、事件与确定性调度；旧推理先以可选兼容适配器运行，不成为 Hub 默认依赖。读旧数据、手动建任务、查看历史和编辑记忆均通过测试；AI 回合明确等待，无模型网络请求。
- [ ] **M1-02 贯通 ACP/MCP**：首版接 ACP v1 stdio 与 `session/new` 的 MCP stdio 桥；至少验证 `memory_search`、项目元数据、`task_create` 与派发/回报。区分用户消息和内部事件；流式输出、完成、取消可靠映射。工具/API 走同一业务服务；把项目元数据从 Node 文件访问分开，不解析文本伪造写入。远程 ACP 或外部 HTTP MCP 不挡本项。
- [ ] **M1-03 第一方与第三方同契约**：把模型调用、规划、工具循环迁到可选 Sous Agent ACP 入口；用真实第一方和至少一个第三方做握手、流式、取消、实际调用工具和边界测试。第三方未限制自带工具、宿主工作区、环境或凭据时，标记不支持主管；不靠提示词、空目录或 ACP 权限回调冒充隔离。
- [ ] **M1-04 绑定与切换**：实现作用域、实例/回合和绑定代次限定的短时凭据，防旧 Agent 或旧 Hub 任期继续写。探测失败保留旧绑定；在途回合收尾或取消后切换。验证不改变旧对话、记忆、项目、任务 ID、待处理队列和已执行中的 Run；新 Agent 用摘要和近期历史启动，不假定私有会话能跨 Agent 恢复。
- [ ] **M1-05 完成剩余模型解耦**：审批/验收建议、摘要与巡检可插拔；无能力分别验证人工、结构化上下文、确定性规则。无主管/无 Node 时工作台可用且状态清楚；不让主管批准自己的请求。确认兼容后才退役旧直连模型调用及旧设置。
- [ ] **M1-06 本地 App 装配**：在现有桌面项目内随包带完整 WebUI，提供真实本机 Hub 和本机身份通道，不信任任意 localhost；打通生命周期、主管设置、能力探测和退出清理，无 Relay/云端页面依赖。先可验证本地聊天闭环；本机执行的发布资格由 M2 决定。离线验收关闭 WAN，使用离线模型及工具，确认新建/查询/对话的持久内容未离开设备。

第一方 ACP 预览已实现真实 ACP v1 stdio 子进程、`session/new` MCP stdio、主对话记忆检索、受限项目资料、手动待分配草稿、增量和按消息序号取消，启动时换模块不换数据库。尚不派发执行任务；本机已可在设置中验证并切换内置主管，探测失败或在途回合保留原绑定。第三方主管的运行边界及切换、附件/会议、跨平台实机仍未完成，M1-02 至 M1-04 保持未勾选。

## M2 · 本机沙盒与授权闭环

已完成并验证 Apple Silicon/macOS 的桌面授权、派发、Guest 审阅和逐文件写回闭环；Windows/Linux/Intel 实机、无人值守授权和云端授权仍未完成。

- [ ] **M2-01 固定版本并验收 Microsandbox**：已固定 Go SDK v0.7.16，并在 Apple Silicon macOS 26.5 用官方 v0.7.16 运行时通过了本地后端、无网络 Guest、控制通道文件导入/修改/读回、宿主原件不变和销毁测试；Windows/Linux/Intel Mac 仍需实测。待定发布分发方式；用同一 Linux Guest 工作负载测试 Apple Silicon、Linux KVM、Windows WHP；记录具体版本/架构、硬件、安装与分发签名、冷/热启、资源占用、Agent 兼容、单文件与目录导入、关网控制、退出销毁和错误处理。Windows 与 Intel Mac 单列实测或不支持依据；未通过验收的平台不启用云控本机。热挂载不是首版门槛；不实现 SmolVM 或 Terrarium 适配，不依赖 Docker。
- [ ] **M2-02 本机授权与使用窗口**：原生选择器支持任意用户可访问位置和文件/目录；本机持有实际路径，云仅持 `project_grant_id`。分别建模逐次授权、明确限时的无人值守授权、导入读取、独立写回及撤权。没有授权、不匹配、到期或无法解析真实对象则拒绝；Host 计时，云端不能加范围或无限续期。明确敏感文件的默认筛选、可见配置及审计；不自动共享家目录或项目外依赖。
- [ ] **M2-03 Guest 生命周期与网络**：宿主薄组件主动连接工作区入口/Relay，不向公网监听，不提供宿主 shell、任意挂载、管理 socket 或通用代理。限制 Guest 的可达网络和宿主 IPC，关公网仍可派发/收结果；模型/依赖出站、结果上报另授权，不转发宿主环境、SSH agent 或宿主密钥。用一个临时 Guest 运行一个 Run；宿主无需保持项目挂载即可接单。无合格 VM、平台不可用或启动失败，不回退宿主执行。
- [ ] **M2-04 数据导入与写回**：按 Run 导入授权内容，Guest 内可写副本；不把宿主项目原件直接作为 Guest 可写卷，不启用自动写回。本机审阅 diff，选择获准写回的变更，校验基线并拒绝覆盖并发宿主编辑；新文件、删除和改名也必须在范围内。用真实仓库和包含文件链接、junction/reparse point、嵌套挂载、目录替换、Git worktree 外部 `.git` 引用的隔离夹具，验证不读写项目边界之外。评估大仓库导入、类文件系统差异和暂存占用。
- [ ] **M2-05 封住旧宿主分支**：迁走 ACP 启动、项目列表/预览/搜索、Git、终端和清理的宿主执行路径；把本地配置/放权和发布签名更新留在可信管理面。验证权限较大的旧 Hub 帧也不能绕过沙盒访问实体机。决定本地 Hub 是否一起沙盒化；能收云指令时，它同样不得充当宿主旁路。
- [ ] **M2-06 失败和撤权验收**：无授权不读取；项目 A/B 不串目录/缓存；完成、取消、到期、断线超时、Guest 卡死、接入组件重启均停止授权窗口并确认销毁 VM 并清理其项目共享配置与临时材料；仅停机不算撤权。不得复用包含用户材料的预热快照；只允许无项目基底预热。若后续实现热挂载，项目跨平台复测只读、仍打开的句柄、Guest 不配合、宿主摘共享失败后的强停与清理；不以 Guest `umount` 返回或 VM 暂停当作撤权。向用户说明已读、已上报的内容不可追回。

本机执行的第一条可运行路径：`sous-sandbox` 在 Apple Silicon / macOS 上用一次性 `--source` 提供授权；从受限文件快照进入无网络 Guest，输出修改/新增/删除清单和前后副本；异常和宿主进程强杀有恢复对账，执行阶段不触碰原项目。本机 CLI 可单独确认一项内容写回，已在真实 Git worktree 验证，保留原件用于冲突恢复。Apple Silicon Desktop 开发包已通过原生选择、独立图形审阅和新增文件写回验收；已跑通本机工作台 → Desktop 私有请求 → Microsandbox；网络 Node 的派发授权、正式分发、跨平台与完整故障矩阵仍未完成；不把 CLI 预览当作 M2 整段验收。

## M3 · 托管工作区与云工作机

独立托管入口已在本机隔离环境完成 HTTPS/WSS 和手机尺寸的工作台验收，支持无主管与同机 ACP；Linux arm64 真实 Guest 已验证运行和重启。没有可用的云执行目标时不发起旧式派发。隔离 HTTPS 工作区已可接入专用参考 worker，手机布局可授权并从新 Guest 续跑成果。实际 Linux 执行宿主、云厂商唤醒和关机、公网真机、多机接入仍需独立验收。

- [ ] **M3-01 托管权威与入口**：一个工作区一个主区域、一个权威 Hub；Hub 和可选云主管同机隔离进程或同区私网，数据与云执行环境就近。静态前端可 CDN，不引入额外前端业务转发。比较复用现有 Relay 与等价授权的托管接入；验证配对/权限、重连、保活、代理超时/缓冲。测试多台 Node 独立接入；一台掉线不阻断其他在线目标，云 Hub 没有本地主管也能从手机手工管理/派发。拒绝自动把仅在本机的数据/任务转云。
- [ ] **M3-02 启动门槛与控制器**：评估云计算与持久存储、区域/驻留、配额/费用，用隔离的 Linux 云环境做首版。只为经过目标选择、依赖、审批、项目上云许可和配额检查的任务保存启动意图。控制器使用独立管理凭据，预构建执行镜像，用短时凭据注册；探活、授权材料和实例代次有效后才执行。草稿、聊天、等待审批/本机不会唤醒云工作机。
  - Linux amd64/arm64 验收构建均通过交叉编译；arm64 在无 KVM 的真实 Guest 中验证拒绝。容量预留、独立 `cloud-controller`、短时一次性引导和 worker 代次隔离已经与真实 HTTPS/Guest 联合验证；厂商使用文件型夹具。已接入独立 AWS EC2 驱动与短时 cloud-init 引导，SDK 本机签名协议和故障测试通过；真实账户内的自有 AMI、Linux/KVM 正向执行和公有云引导仍待验收。
- [ ] **M3-03 回收和成果**：先实现评审阈值（5 分钟仅作试测）及保活、排空取消、新任务竞态、长 Run/内部审批、持久化失败保留现场。确认未提交改动与产物可恢复后再释放计算；独立设置存储留存/删除与费用，重建刷新凭据，不保证内存继续。界面清楚显示等待、启动、准备、运行、失败、回收或因未落盘保留的原因，允许取消。
  - Hub 已在队列事务中执行无在途且近期确认空闲的排空栅栏；厂商确认前不解锁下一代。手机工作台已显示启动、排队、回收和不可用提示。EC2 驱动持久保存潜在发请求及终止证据，未观察确切终态、根盘遗留或其他不确定状态均不释放下一代；真实 AWS 磁盘、实例回收和费用仍待验收。
- [ ] **M3-04 对账与端到端**：按工作区和实例/派发代次幂等重试，验证控制器重启、超时、旧 Node 回连、启动/排空时取消、孤儿实例、新任务重启和已执行但结果不确定。副作用不明先核对，不自动重跑。验收：所有个人电脑关机 → 手机建任务与审批 → 从零唤醒 → 运行 → 成果持久化 → 空闲释放 → 再唤醒可恢复；同时验证仅在离线本机的任务仍明确等待。
- [ ] **M3-05 快路径性能门槛**：用相同脚本跑无工具聊天、多次依赖工具调用、派发和取消、弱网断线、大 diff 并发；本地/同区/约 80 和 180 ms RTT 与抖动分组，再用真实 Agent 和模型复测。建立暖连接 80 ms RTT、持久化确认 p95 ≤ 300 ms 的拟议内部基线，首段正文、重连、VM/项目准备另列实测。实现流式且不阻塞，增量可丢而最终回复、业务状态可按序恢复；大传输队列不得拖住审批/取消。先减少串行 WAN 调用和反代转发，再按排队、CPU、I/O 或连接指标扩容；不靠关闭审核或放宽权限达标。

## M4 · 高级组合与后续范围

- [ ] **M4-01 云／本地异地主管**：验证受认证的 Sous 传输适配器、ACP stdio 桥和受限 MCP 往返，不要求第三方直接监听。分别演示云 Hub + 本地 Codex 类主管、本地 Hub + 云 Sous Agent + 远程网页；用故障测试验证断网、Hub/主管分别离线、凭据撤销、旧回合输出，以及工作区哪些内容会传给远端 Agent。按串行工具次数和实际 P95 评估是否推荐。
- [ ] **M4-02 外部 MCP 与多入口**：用独立、可撤销的工作区工具授权验证外部 MCP 客户端与桌面访问同一权威 Hub；兼容性按客户端验证，不默认承诺任一客户端能连本地接口。证明不经内部主管也可管理项目任务；切换本地/云工作区不串数据、缓存、凭据或 Node 权限，不做双主。
  - 托管端独立 Streamable HTTP MCP、单项目授权/撤销、只读与草稿权限，已用官方 SDK 和手机浏览器 E2E 验证。仅支持预注册 HTTPS 回调，真实第三方产品和桌面/本机/云切换的组合仍未验收。
- [ ] **M4-03 实时挂载可行性**：只有真实数据表明副本导入或 IDE 联动瓶颈才推进。先短时宿主只读，再评审独立的实时写授权；达到 M2-06 的强撤权、跨平台、性能和 UX 门槛前不发布。默认副本写回流程保持可用。
- [ ] **M4-04 归档验收结果与长效文档**：发布一张实际支持组合/平台矩阵，列出不支持的环境与原因、真实测量及限制；每一能力完成后更新实际架构和已定接口，所有必要任务完成后按仓库规则将长期结论整理进 `docs/`。未获批准的增强项不算已交付，不把计划写成现状。

**明确不在首版**：插件市场/动态装载、跨 Hub 双主同步、跨区状态双写与自动故障切换、自动公网直连切换、常驻云桌面或多云编排、内存透明恢复、默认实时写挂载、无隔离的远程 Node。
